# РемТехСад

Интернет-магазин товаров для сада, садовой техники, снегоуборочного инвентаря и запчастей, с заявками на ремонт. Публичный сайт на русском и закрытая админка для сотрудников. Обмен с 1С, онлайн-оплата и доставка подключены через интерфейсы с локальными заглушками — реальные провайдеры ещё не выбраны (см. `docs/handoff.md`).

Стек: Next.js (App Router) + TypeScript + SQLite (встроенный `node:sqlite`). Причины выбора — `docs/adr/ADR-001-stack.md`.

## Что нужно на Windows

- **Node.js LTS 24 или новее** с npm: https://nodejs.org (при установке оставьте галочку «Add to PATH»). Проверка: `node -v`, `npm -v`.
- Всё. **Сервер базы данных не нужен**: БД — один файл `data/rts.sqlite`, его создаёт сама команда миграции.
- **Open Server не нужен.** Он даёт PHP + Apache/Nginx + MySQL, а этот проект — приложение на Node.js со своим встроенным веб-сервером (`next`). Open Server предназначен для локальной разработки PHP-сайтов и не годится для production; запускать этот сайт через него не требуется и не нужно.
- Docker не нужен.

## Чистая установка (проверено командами)

В PowerShell или cmd, в папке проекта:

```
npm install
copy .env.example .env
npm run db:migrate
npm run import:yml -- путь\к\catalog.yml
npm run admin:create -- ваш-логин
npm run dev
```

Что делает каждая команда:

| Шаг | Что происходит |
|---|---|
| `npm install` | ставит зависимости по `package-lock.json` (около полминуты) |
| `copy .env.example .env` | локальные настройки; в разработке файл можно оставить пустым |
| `npm run db:migrate` | создаёт `data/rts.sqlite` и применяет миграции (повтор безопасен) |
| `npm run import:yml -- <файл>` | загружает **настоящий** каталог из YML-выгрузки (185 категорий, 1214 товаров из `catalog.yml`; 4 товара без цены в отчёте ошибок). Предпросмотр без записи: добавьте `--preview`. Фото скачиваются только с флагом `--images` (нужна сеть) — без него сайт показывает фото по ссылке источника |
| `npm run admin:create -- логин` | создаёт администратора. Пароль спросят скрытым вводом (или возьмут из переменной `ADMIN_PASSWORD` в этом окне терминала). Пароль нигде не печатается и не хранится в репозитории |
| `npm run dev` | сервер разработки на http://localhost:3000 |

Проверка: http://localhost:3000/api/health отвечает `{"status":"ok", ...}`; админка — http://localhost:3000/admin/login.

Если порт 3000 занят: `npm run dev -- -p 4000`.

Демо-набор для локальной проверки: `npm run seed:demo` (способы получения и оплаты; тестовая «онлайн (ТЕСТ)» — только вне production; **выдуманных отзывов, рейтингов, остатков и тарифов нет**). Каталог берите командой `import:yml` или `npm run seed:demo -- --catalog путь\к\catalog.yml`.

## Открыть сайт на телефоне по Wi-Fi

1. Телефон и компьютер — в одной сети Wi-Fi.
2. Запустите `npm run dev -- -H 0.0.0.0` (слушать на всех адресах).
3. Узнайте адрес компьютера: `ipconfig` → «IPv4-адрес» (например, `192.168.1.25`).
4. На телефоне откройте `http://192.168.1.25:3000`.
5. Если не открывается — брандмауэр Windows: разрешите Node.js для частной сети. После проверки закройте `-H 0.0.0.0` (обычный `npm run dev` слушает только этот компьютер).

Подробнее — `docs/local-setup.md`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер разработки, порт 3000 |
| `npm run build` / `npm run start` | production-сборка / запуск собранного (нужны `SITE_URL`, `SESSION_SECRET`) |
| `npm run check` | единая проверка: типы, линтер, тесты |
| `npx vitest run tests/<путь>.test.ts` | один файл тестов |
| `npm run db:migrate` | БД и миграции |
| `npm run db:seed` / `npm run seed:demo` | базовые сиды / то же + отчёт и необязательный каталог |
| `npm run import:yml -- <файл> [--preview] [--images]` | импорт каталога |
| `npm run admin:create -- <логин>` | создать администратора |
| `npm run backup` / `npm run restore -- <файл> [--force]` | резервная копия и восстановление (`docs/backup-restore.md`) |
| `npm run e2e:live` | сквозная проверка работающего сервера по HTTP (`BASE_URL=…`, только на копии данных) |
| `npm run a11y:live` | замер бюджета JS страниц работающего production-сервера |

## Как устроен код

- `src/app` — страницы и API, только тонкие обработчики. Публичные страницы — в `src/app/(shop)/…`.
- `src/domain` — бизнес-логика (каталог, цены, заказы, покупатели, админ, контент, заявки, аналитика, SEO).
- `src/server` — конфигурация (`config.ts`), БД (`db/`: подключение, миграции, репозитории), HTTP-примитивы (`http/`).
- `src/integrations` — порты внешних сервисов (1С, оплата, доставка, почта) и их заглушки.
- `src/ui` — компоненты и тема (`theme.css`, CSS-переменные). Любой факт, которого нет (адрес, телефон, логотип), выводится как метка `[… — впиши]`.
- `migrations/NNNN_name.sql` — только вперёд, применённые файлы не менять.
- `tests/` — Vitest; каждый тест получает свою БД в памяти.

Данные локально — в `data/` (не попадает в git): `rts.sqlite`, `uploads/`, `backups/`, `onec-inbox/`, `onec-outbox/`.
