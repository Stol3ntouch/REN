# Переменные окружения

Образец — `.env.example` (только имена, без значений). Реальные значения хранятся в `.env` (в `.gitignore`) или в настройках процесс-менеджера/хостинга. Пустая строка считается «не задано». Значения секретов не логируются и не попадают в ответы; сообщения об ошибках конфигурации называют только имена.

Читает переменные `src/server/config.ts` (zod-схема), кроме отмеченных отдельно.

## Основные

| Переменная | Назначение | В production |
|---|---|---|
| `NODE_ENV` | `development` / `production` / `test`. `next dev` и `next build`/`start` выставляют сами | выставляется `next start` |
| `APP_ENV` | `production` включает режим production и при другом `NODE_ENV` | по необходимости |
| `SITE_URL` | публичный адрес сайта (`https://…`, без завершающего «/»): canonical, sitemap, ссылки в письмах, хост редиректа на HTTPS | **обязательна** |
| `SESSION_SECRET` | случайная строка не короче 32 символов; подпись гостевых ссылок на заказ и сессионная криптография. Смена обнуляет выданные гостевые ссылки на заказы | **обязательна** |
| `DATABASE_PATH` | путь к файлу SQLite (по умолчанию `data/rts.sqlite`) | диск должен быть постоянным |
| `DATA_DIR` | папка данных: `uploads/`, `backups/`, `onec-inbox/`, `onec-outbox/` (по умолчанию `data`) | постоянный диск |
| `TRUST_PROXY` | `true` — доверять заголовку `X-Forwarded-For` для определения IP (лимиты запросов). Только за своим обратным прокси | `true` за прокси, иначе `false` |
| `HTTPS_REDIRECT` | `off`/`false`/`0` отключает только 301-редирект HTTP→HTTPS (читает `src/proxy.ts`). Для прокси, который не умеет передавать верный `X-Forwarded-Proto`. В обычном production не задавать | не задавать |
| `NEXT_DIST_DIR` | отдельная папка сборки Next.js (читает `next.config.ts`), чтобы проверка не затирала `.next` работающего dev-сервера | не нужна |
| `IMAGE_HOST_ALLOWLIST` | хосты, с которых импорт может скачивать фото (через запятую; по умолчанию `champion.ru`) | по решению владельца (права на фото!) |

## Почта (SMTP)

Без `MAIL_HOST` и `MAIL_FROM` письма не отправляются, а ждут в очереди `email_outbox`.

| Переменная | Назначение |
|---|---|
| `MAIL_HOST`, `MAIL_PORT` | SMTP-сервер и порт |
| `MAIL_USER`, `MAIL_PASSWORD` | учётные данные SMTP (секрет) |
| `MAIL_FROM` | адрес отправителя |
| `MAIL_TO` | запасной адрес менеджеров, если получатели в настройках пусты |

## Интеграции

| Переменная | Назначение |
|---|---|
| `ONEC_MODE`, `PAYMENT_MODE`, `DELIVERY_MODE` | `stub` (по умолчанию) или `live`. Реализаций `live` пока нет — работают только заглушки (`docs/handoff.md`) |
| `PAYMENT_PROVIDER` | пусто или `test` вне production — тестовая оплата; в production без настоящего провайдера онлайн-оплаты нет |
| `PAYMENT_API_KEY` | ключ платёжного провайдера (секрет; провайдер пока не выбран) |
| `PAYMENT_WEBHOOK_SECRET` | секрет подписи webhook платёжной системы (HMAC-SHA256, заголовок `x-rts-signature: sha256=<hex>`). Пусто вне production — случайный на процесс; в production задать |

## Разовые

| Переменная | Назначение |
|---|---|
| `ADMIN_PASSWORD` | пароль для `npm run admin:create` без интерактивного ввода. Задавайте на одну команду; в `.env` и репозиторий не записывайте |

## Что обязательно в production

`SITE_URL`, `SESSION_SECRET`; рекомендуется `PAYMENT_WEBHOOK_SECRET` (если подключена оплата), `TRUST_PROXY=true` (за прокси), SMTP (`MAIL_*`). Без `SITE_URL` и `SESSION_SECRET` `next start` не запустится и назовёт недостающие имена.
