# Локальный запуск на Windows

Короткая версия — в `README.md`. Здесь — подробности и частые проблемы.

## Почему не нужен Open Server и сервер БД

- Сайт — приложение Node.js: `npm run dev` поднимает собственный веб-сервер (Next.js). Apache/Nginx/PHP из Open Server не используются.
- База данных — файл SQLite (`data/rts.sqlite`) через встроенный в Node.js модуль `node:sqlite`. Ни MySQL, ни PostgreSQL ставить не нужно.
- Open Server предназначен для локальной разработки, а не для production. Production описан в `docs/deployment.md`.

## Что должно быть установлено

| Что | Версия | Проверка |
|---|---|---|
| Node.js | 24 LTS или новее | `node -v` |
| npm | идёт с Node.js | `npm -v` |
| Git | по желанию | `git --version` |

## Шаги с нуля

```
npm install
copy .env.example .env
npm run db:migrate
npm run import:yml -- путь\к\catalog.yml
npm run admin:create -- ваш-логин
npm run dev
```

1. **`npm install`** — предупреждения про «install-scripts blocked» и «vulnerabilities» ожидаемы: заблокированные скрипты (`unrs-resolver`) ничему не мешают, а замечания `npm audit` касаются только инструментов разработки (линтер), не кода сайта на сервере.
2. **`.env`** — в разработке можно оставить пустым. Что означает каждая переменная — `docs/env.md`. Значения секретов в git не попадают (`.env` в `.gitignore`).
3. **`db:migrate`** — создаёт папку `data/`, файл БД и таблицы.
4. **`import:yml`** — каталог берётся только из реальной выгрузки. Сначала посмотрите предпросмотр: `npm run import:yml -- файл.yml --preview`. Повторный импорт того же файла ничего не дублирует. Поля, которые вы правили вручную в админке (при включённой ручной правке), импорт не перезаписывает.
5. **`admin:create`** — пароль вводится скрыто. Без терминала (скрипты) можно передать его переменной окружения на одну команду: в PowerShell `$env:ADMIN_PASSWORD='…'; npm run admin:create -- логин; Remove-Item Env:ADMIN_PASSWORD`. Не записывайте пароль в `.env` и в репозиторий.
6. **`npm run dev`** — http://localhost:3000. Админка: `/admin/login`, вход по логину (или email) и паролю, созданным на шаге 5.

## Проверка, что всё работает

- `http://localhost:3000/api/health` → `{"status":"ok","migrationVersion":…}`.
- Главная, `/catalog`, карточка товара, добавление в корзину, оформление заказа с оплатой при получении.
- `/admin/integrations` показывает 1С, оплату, доставку, почту как **«заглушка»** (`connected:false`) — это правда: реальные сервисы не подключены.
- Автоматические проверки: `npm run check` (типы, линтер, тесты). Сквозная проверка живого сервера: `BASE_URL=http://localhost:3000 npm run e2e:live` — **создаёт заказ и заявку**, запускайте на копии данных.

## Сайт на телефоне по Wi-Fi

См. раздел в `README.md`: `npm run dev -- -H 0.0.0.0`, затем `http://<IPv4 компьютера>:3000` на телефоне. Разрешите Node.js в брандмауэре для частной сети. Помните: в dev-режиме cookie без флага Secure, редиректа на HTTPS нет.

## Тестовая оплата

Метод «онлайн (ТЕСТ)» создаётся сидом (`npm run db:seed`) и выключен по умолчанию. Включается переменной `PAYMENT_PROVIDER=test` (только вне production). Страница оплаты помечена «ТЕСТОВАЯ ОПЛАТА». В production этот метод принудительно отключается.

## Почта

Без `MAIL_HOST` и `MAIL_FROM` письма не отправляются, а попадают в очередь `email_outbox` (видна в `/admin/mail`). Это не потеря: после настройки SMTP воркер отправит накопленное (не более 3 попыток на письмо).

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `EADDRINUSE` порт 3000 занят | другой процесс: `npm run dev -- -p 4000` |
| Пустой каталог | не выполнен `import:yml` |
| `Некорректная конфигурация окружения` | в production не заданы `SITE_URL` / `SESSION_SECRET` (`docs/env.md`) |
| Ошибка про `node:sqlite` | старый Node.js — обновите до 24+ |
| `restore` не может заменить файл | сервер ещё запущен и держит БД — остановите его |
| Фото товаров не видны | без `--images` показываются по ссылке источника (champion.ru); нужна сеть; права на фото — открытый вопрос владельцу |
| Не удаётся удалить папку `data` | остановите сервер |

## Сброс локальных данных

Остановите сервер и удалите папку `data` — следующий `db:migrate` создаст чистую БД. Перед этим можно сделать `npm run backup`.
