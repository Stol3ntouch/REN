# Передача проекта

## Что передано

Исходный код, миграции, тесты, документация, пример окружения (`.env.example`), конфигурация CI. Работает локально по `README.md`: публичный сайт (главная, каталог с поиском/фильтрами/сортировкой, карточка товара, корзина, оформление для гостя и вошедшего, кабинет, избранное, сравнение, заявки на ремонт/звонок/вопрос/обратная связь, отзывы с модерацией, страницы контента, SEO), админка с ролями `admin`/`manager` (заказы, заявки, модерация, каталог, импорт YML с предпросмотром, контент, настройки, сотрудники, аналитика, аудит, журнал интеграций и почты), резервные копии (`backup`/`restore`).

Каталог — реальная выгрузка (1214 товаров, 185 категорий); 4 товара без цены в файле не загружены (id 217943, 217944, 217946, 217947) — нужна цена от владельца.

## Что НЕ проверялось

- Работа с реальными 1С, платёжным провайдером, доставкой и SMTP-сервером: ни одно внешнее подключение не выполнялось.
- CI (`.github/workflows/ci.yml`): файл написан, **ни разу не запускался** в GitHub Actions.
- Production-развёртывание, реальный TLS и поведение за обратным прокси: чек-лист в `docs/deployment.md` не выполнялся.
- Скачивание фото с живого champion.ru в этой сборке; нагрузка (одновременные покупатели), долгая работа воркера почты.
- Браузеры: размеры 360/768/1280 px и фокус с клавиатуры проверены в одном встроенном браузере (Chromium) на dev-сервере; Safari/Firefox/реальные телефоны — нет. Скринридеры — нет. Playwright не устанавливался: сквозные проверки — это интеграционные тесты и HTTP-скрипт, а не управление браузером (подробности — `docs/qa-report.md`).
- Node.js: сквозные прогоны этой сверки выполнены на Node 22.22.2 (в окружении проверки; `package.json` требует ≥ 24), ADR зафиксировал проверку на 26.

## Известные ограничения

- Два лимита производительности: один процесс приложения и один файл SQLite; несколько реплик не поддерживаются.
- В `/admin/staff` нельзя сменить пароль сотрудника (деактивировать и завести нового; администратора — `admin:create`).
- Удаление старых резервных копий и выгрузка копий в облако не автоматизированы.
- Страница `/pay/test/…` и метод оплаты «онлайн (ТЕСТ)» — только для разработки.
- Динамическая работа с файлами в `src/media/store-image.ts` даёт предупреждение сборки Turbopack («Dynamic filesystem access…»); сборка проходит, на работу не влияет.
- `npm audit`: 5 замечаний high в инструментах разработки (`braces` через `eslint-config-next`), не в серверном коде.

## Открытые вопросы владельцу

1. **Фото и описания из фида champion.ru**: есть ли право использовать? Хранить копии у себя (`--images`) или показывать по ссылке? Без ответа публиковать нельзя.
2. **Реквизиты** организации (название, ИНН/ОГРН, адрес) для подвала и документов; **часы работы**, **email** магазина, **соцсети**, **координаты** для карты. Сейчас — метки `[… — впиши]` и адрес «Талдом, Садовый переулок д10» из настроек.
3. **Логотип и фирменные цвета** — файл логотипа.
4. **Юридические тексты**: политика обработки ПДн (черновик, нужна проверка юристом), условия, доставка и оплата, гарантия и возврат, FAQ.
5. **SMTP**: сервер, адрес отправителя, получатели уведомлений (менеджеры, администратор).
6. **Платёжный провайдер** (какой, ставки, фискализация/чеки) и **службы доставки** (какие, тарифы).
7. **1С**: конфигурация (УНФ / УТ / Розница), партнёр, тестовый контур — вопросы в `docs/1c.md`.
8. **Домен и хостинг** (с постоянным диском), TLS, кто администрирует сервер, RPO/RTO и расписание резервных копий.
9. **4 товара без цены** (217943, 217944, 217946, 217947): указать цену или оставить скрытыми.
10. Тексты «О компании», преимущества, услуги ремонта и их цены; будут ли акции, новости, слайды (сейчас пусто — выдуманного нет).
11. Нужно ли подтверждение email при регистрации и двухфакторный вход для сотрудников (`docs/security.md`).

## Как принять работу

1. `README.md` → чистая установка (шаги проверены в чистой копии: `npm install`, `db:migrate`, `import:yml`, `admin:create`, `seed:demo`, запуск dev).
2. `npm run check` — типы, линтер, тесты. `npm run build`.
3. `docs/qa-report.md` — что именно запускалось и с каким результатом.
4. `docs/deployment.md` — план выхода в production.
