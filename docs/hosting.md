# Где и как запускать магазин: OpenServer, сервер, Vercel, Supabase

Документ для владельца. Здесь только описание: ничего не публиковалось, не покупалось и не разворачивалось. Общий чек-лист выхода в production — `docs/deployment.md`, переменные — `docs/env.md`.

Главное, что нужно знать: магазин — приложение на Node.js. Его данные лежат в **одном файле** (`data/rts.sqlite`), а загруженные фото — в **папке на диске** (`data/uploads/`). Поэтому ему нужен компьютер или сервер, где диск не пропадает между запусками, и один постоянно работающий процесс.

## 1. Что где работает сейчас

| Площадка | Статус | Пояснение |
|---|---|---|
| OpenServer на Windows | работает с настройкой | OpenServer здесь только «входная дверь» (домен и, возможно, обратный прокси). Сам магазин запускается командой Node.js. Как привязать домен — см. раздел 2, пункт про домен: этот пункт нужно проверить по документации OpenServer |
| Обычный VPS или свой сервер (Windows/Linux) | работает с настройкой | Основной рекомендуемый путь: `docs/deployment.md` |
| Vercel | не работает без доработки | Диск не сохраняется между запросами, SQLite-файл и фото там жить не могут (раздел 3) |
| Supabase | только база | Это PostgreSQL и хранилище файлов, а не место, где запускается сайт. Подключение магазина к ней требует переписывания кода (раздел 4) |

## 2. OpenServer на Windows

### Что понадобится

- **Node.js 24 или новее** (LTS) с npm: https://nodejs.org. В `package.json` указано `"node": ">=24"`. Проверка: `node -v`.
- PHP, MySQL, Apache/Nginx из OpenServer магазину **не нужны**: у него свой встроенный веб-сервер и своя база (файл SQLite). OpenServer нужен только если вы хотите воспользоваться им для привязки домена.
- Docker и отдельный сервер базы не нужны.

### Шаги

1. **Положите проект** в постоянную папку на диске, где есть место и право записи, например `D:\sites\remtehsad`. Не кладите в папку, которую что-то чистит или синхронизирует (корзина, временные файлы). Папка `data\` внутри будет содержать базу и фото.
2. **Установите зависимости** (PowerShell или cmd в папке проекта):
   ```
   npm install
   ```
3. **Создайте файл настроек**:
   ```
   copy .env.example .env
   ```
   Откройте `.env` и заполните (имена из `.env.example`, подробности — `docs/env.md`):
   - `SITE_URL` — публичный адрес сайта целиком, с `https://`, без «/» в конце. Обязательна в production.
   - `SESSION_SECRET` — случайная строка не короче 32 символов. Обязательна в production. Сгенерируйте командой и вставьте результат в `.env`, не показывая и не пересылая его:
     ```
     node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
     ```
     Хранить значение нужно только на этом компьютере (и в вашем менеджере паролей).
   - `TRUST_PROXY` — `true`, если перед магазином стоит ваш прокси (OpenServer, IIS, Nginx, Caddy); `false`, если порт открыт напрямую. В production задавайте явно: иначе лимиты по IP не работают, а при старте будет предупреждение.
   - `HTTPS_REDIRECT` — обычно **не задавать**. Только если прокси завершает HTTPS, но не умеет передавать верный `X-Forwarded-Proto`, и возникает бесконечный редирект: тогда `off`.
   - `MAIL_HOST`, `MAIL_PORT`, `MAIL_USER`, `MAIL_PASSWORD`, `MAIL_FROM`, `MAIL_TO` — почта (SMTP). Без них письма копятся в очереди и не уходят.
   - `DATABASE_PATH`, `DATA_DIR` — по умолчанию `data\rts.sqlite` и `data\`; менять только если нужен другой диск.
4. **Создайте базу и таблицы**:
   ```
   npm run db:migrate
   ```
5. **Загрузите каталог** (сначала предпросмотр, потом настоящий импорт):
   ```
   npm run import:yml -- путь\к\catalog.yml --preview
   npm run import:yml -- путь\к\catalog.yml
   ```
   Ключ `--images` скачивает копии фото (нужна сеть; права на фото — вопрос к вам, `docs/handoff.md`).
6. **Создайте администратора.** Проще всего — скрытый ввод пароля:
   ```
   npm run admin:create -- ваш-логин
   ```
   Если нужно передать пароль переменной (на одну команду, не записывая в `.env`):
   - PowerShell: `$env:ADMIN_PASSWORD='ваш-пароль'; npm run admin:create -- ваш-логин; Remove-Item Env:ADMIN_PASSWORD`
   - Git Bash: `ADMIN_PASSWORD='ваш-пароль' npm run admin:create -- ваш-логин`
7. **Соберите и запустите в рабочем режиме**:
   ```
   npm run build
   npm start
   ```
   `npm start` слушает порт **3000**. Другой порт: `npx next start -p 4000`. Если `SITE_URL` или `SESSION_SECRET` не заданы, сервер остановится и назовёт недостающие имена. Проверка: `http://localhost:3000/api/health` должен вернуть `"status":"ok"`.
8. **Чтобы работало постоянно**, обычное окно терминала не годится (закроете — сайт остановится). Варианты, нужно проверить, что подходит вам:
   - Планировщик заданий Windows: задача «при запуске компьютера» с командой `npm start` в папке проекта, с перезапуском при сбое (параметры задачи проверьте в самом Планировщике);
   - служба Windows через сторонние программы (например NSSM) — проверить по документации выбранной программы;
   - менеджер процессов pm2 — проверить по документации pm2 (https://pm2.keymetrics.io) работу на Windows.
   Подробнее о требованиях: `docs/deployment.md`, раздел 2.
9. **Домен и HTTPS.** Приложение само HTTPS не делает: перед ним нужен прокси с сертификатом, который передаёт `Host`, `X-Forwarded-For` и **`X-Forwarded-Proto: https`**. Без `https` в этом заголовке не включится защитный заголовок HSTS.
   - **OpenServer:** *не подтверждено.* На странице документации версии 5 (https://ospanel.io/docs/) упомянуты Apache, Nginx, PHP, базы данных и доменные настройки (в «Настройки → Домены»), но модуль Node.js и проксирование на порт Node там не описаны (страница помечена устаревшей). Проверить по официальной документации актуальной версии: https://ospanel.io/docs/. Не утверждаем, что OpenServer умеет проксировать на порт Node.
   - **Проверенная альтернатива по принципу работы:** поставить перед магазином обратный прокси, умеющий это точно: Nginx, Caddy или IIS с ARR (документация: https://nginx.org/ru/docs/, https://caddyserver.com/docs/, https://learn.microsoft.com/iis/). Они пересылают запросы на `127.0.0.1:3000` и сами получают сертификат (например, Let's Encrypt). Конкретные файлы настройки здесь не приводятся: сверьтесь с документацией выбранной программы.
   - Порт приложения закройте от интернета, наружу — только 80 и 443.
10. **Где лежат данные.** `data\rts.sqlite` (база), `data\uploads\` (фото), `data\backups\` (копии), `data\onec-inbox\`, `data\onec-outbox\`. Эти папки не попадают в git.
11. **Резервные копии.**
    ```
    npm run backup
    npm run backup -- --out D:\резерв
    ```
    Копии храните вне диска приложения; расписание — Планировщик заданий. Восстановление (`npm run restore -- <файл>`, сначала остановив сайт) — `docs/backup-restore.md`.
12. **Обновление версии.** Сделайте `npm run backup`, остановите сайт, получите новую версию кода, `npm install`, `npm run build`, запустите снова (миграции применяются сами, только вперёд). Откат — только восстановлением копии. Подробно: `docs/deployment.md`, раздел 7.

## 3. Vercel

Честный вывод: **без доработки магазин на Vercel не заработает**, и «деплоя в один клик» нет.

Почему. По документации Vercel (https://vercel.com/docs/functions/runtimes, раздел «File system support») у функций файловая система только для чтения, записывать можно лишь во временную папку `/tmp` (до 500 МБ), которая не является постоянным хранилищем. Магазин же хранит базу в файле SQLite и фото на диске, а ещё запускает фоновые задачи внутри процесса (воркер почты в `src/instrumentation.ts`/`src/server/startup.ts`). Постоянного процесса, как на сервере, там нет. Актуальные лимиты, версии Node.js и цены — проверить по официальной документации: https://vercel.com/docs.

Варианты:

- **A. Доработать приложение.** Вынести базу во внешнюю PostgreSQL, а фото — в объектное хранилище. Что для этого переписывается:
  - слой доступа к данным: 37 файлов `src/server/db/repositories/*` и SQL в `src/domain/catalog/store.ts` и `src/domain/seo/store.ts`; драйвер `node:sqlite` заменить на драйвер PostgreSQL;
  - код сейчас синхронный (`ADR-003`), у PostgreSQL обращения асинхронные: транзакции и вызывающий код придётся менять;
  - миграции `migrations/*.sql` перевести на диалект PostgreSQL (раздел 4);
  - фото: запись и чтение `data/uploads` (`src/media/store-image.ts`, маршрут `src/app/api/catalog/media/…`) заменить на хранилище;
  - воркер почты и фоновые задачи заменить на задания по расписанию (cron Vercel — документация https://vercel.com/docs/cron-jobs) или на очередь;
  - резервные копии (`npm run backup`) пересмотреть: они рассчитаны на файл SQLite.
  Оценка объёма: порядка **8–12 отдельных задач** (слой данных, миграции, тесты на новую базу, хранилище фото, фоновые задачи, резервные копии, проверка). Это грубая прикидка по числу затронутых модулей, не обещание сроков.
- **B. Не использовать Vercel для этого приложения.** Запускать на Windows-сервере или VPS (раздел 2 и `docs/deployment.md`). Это работает сейчас без переписывания кода.

Публикация на Vercel в рамках этого документа не выполнялась.

## 4. Supabase

Supabase — это в первую очередь PostgreSQL, авторизация и хранилище файлов, **а не хостинг для Next.js-сайта** (проверить состав услуг по официальной документации: https://supabase.com/docs). Магазин сейчас с Supabase не работает; подключение — доработка.

Как выглядел бы перенос:

- **Схема.** Файлы `migrations/*.sql` (по ним 12 файлов) переписать под PostgreSQL. Заметные различия SQLite и PostgreSQL, которые есть в проекте:
  - полнотекстовый поиск на FTS5 (`migrations/0150_catalog_search.sql`, `src/domain/catalog/fts.ts`) в PostgreSQL заменяется встроенным полнотекстовым поиском (или расширением); поведение поиска по-русски придётся перепроверить;
  - функция `json_each` (используется в запросах каталога) и JSON вообще работают иначе;
  - тип первичного ключа `INTEGER PRIMARY KEY`/автонумерация, форматы дат и функции времени, `INSERT OR …`, `ON CONFLICT`, триггеры — синтаксис отличается;
  - проверки целостности в миграциях потребуют проверки на новой базе.
- **Строка подключения.** Берётся в панели Supabase (проверить по документации: https://supabase.com/docs/guides/database/connecting-to-postgres); в приложении сейчас такой переменной нет, её надо будет завести и описать в `docs/env.md`. Секрет в репозиторий не кладётся.
- **Фото.** Заменить папку `uploads` на Supabase Storage (https://supabase.com/docs/guides/storage), проверить политику доступа и ограничения размера.
- **Код.** Те же правки, что в разделе 3, вариант A: репозитории на синхронном `node:sqlite` переписать под PostgreSQL. Решение о причинах выбора SQLite и условиях перехода — `docs/adr/ADR-001-stack.md` («Условия пересмотра»), про синхронные репозитории — `ADR-003`. Доменный код при этом, по ADR-001, меняться не должен.

Рекомендуемый порядок: **сначала запустить магазин на Windows-сервере или VPS** (всё уже работает), собрать заказы и обратную связь, а перенос базы на PostgreSQL планировать позже отдельным проектом, если появится причина (несколько экземпляров, рост нагрузки, требование хостинга).

## 5. Чек-лист перед открытием для клиентов

- [ ] Пройден `docs/deployment.md` целиком (хостинг, домен, HTTPS, прокси, переменные, резервные копии, мониторинг).
- [ ] Прочитан `docs/security.md`: что защищено, а что нет.
- [ ] `SITE_URL`, `SESSION_SECRET`, `TRUST_PROXY` заданы; `HTTPS_REDIRECT` не задан (если не нужен); `PAYMENT_PROVIDER=test` не задан.
- [ ] Все метки-заглушки `[… — впиши]` (адрес, телефон, часы, email, реквизиты, логотип) заменены в админке `/admin/content/settings`.
- [ ] Юридические страницы утверждены юристом.
- [ ] Настроена почта (SMTP), в `/admin/mail` нет накопившейся очереди; тестовое письмо дошло.
- [ ] Пароль администратора создан на этом сервере (`npm run admin:create`) и надёжен; учётные записи разработки не переносились.
- [ ] Проверены `/api/health`, замок HTTPS, `Strict-Transport-Security`, вход в админку, тестовый заказ и заявка (удалите их после проверки).
- [ ] Настроен `npm run backup` по расписанию, копии хранятся вне сервера, восстановление проверено.
- [ ] Порт приложения закрыт от интернета.
