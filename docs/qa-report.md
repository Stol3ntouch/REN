## Сквозные сценарии

**Интеграционные тесты (`tests/e2e/*`, через домен и обработчики):** гость — поиск → карточка → корзина → заказ (цена сервера, подмена игнорируется); двойной submit с одним ключом даёт один заказ; вошедший — регистрация, повторный вход, история заказов; чужой заказ (другой пользователь, чужой гость) → 404; менеджер → операция администратора → 403, обработчик не вызван; смена статуса сотрудником и запрет недопустимого перехода; повтор webhook не меняет заказ второй раз; предпросмотр импорта ничего не пишет; формы заявок (успех/без согласия); сбой обмена с 1С → письмо `integration.failed`; подключения при старте (популярность, почта) и их видимость из другого экземпляра модуля; seed:demo; гигиена репозитория (`.env.example`, секреты, выдуманное содержимое).

**Живой сервер по HTTP (`npm run e2e:live`)** на production-сборке (порт 4000, копия БД): 33 проверки, 0 ошибок. Включено: публичные страницы 200; заголовки CSP/HSTS/nosniff; поиск находит товар; корзина — чужой Origin 403, подмена суммы игнорируется; **оформление заказа через серверное действие как HTML-форму → переход на страницу заказа; повтор с тем же ключом ведёт на тот же заказ**; заказ без токена и несуществующий → 404; заявка на звонок 201 / без согласия 400 / чужой Origin 403; webhook с неверной подписью 401; `/admin*` и `/account/orders` без входа → редирект на вход; POST импорта без сессии отклонён. В собранном приложении подтверждено: «популярные» сортируются по реальным заказам (источник подключён `instrumentation`), письма о заказе и заявках попадают в `email_outbox` (почта подключена).

**Не покрыто живым прогоном:** вход покупателя и история заказов в браузере/по HTTP (покрыто тестами), смена статуса заказа менеджером в интерфейсе (тест), повтор настоящего webhook провайдера (тест на тестовом провайдере). Playwright не ставился.

## Доступность и адаптив

- **Контраст** (`tests/a11y/contrast.test.ts`, расчёт по CSS-переменным темы): 14 пар «текст/фон» ≥ 4.5:1; кольцо фокуса ≥ 3:1 на белом и на светлой поверхности. Найдено и исправлено: синее кольцо фокуса на тёмном подвале давало < 3:1 → в подвале кольцо светлое.
- **Горизонтальный скролл** (встроенный браузер, эмуляция 360×800, 768×900, 1280×900, измерение `scrollWidth` и поиск элементов за правым краем): публичные главная, каталог (раздел), карточка товара, корзина (с товаром), оформление, контакты — без скролла на всех трёх размерах. Админка: обзор, заказы, импорт, аналитика, интеграции, заявки, настройки, сотрудники, аудит, покупатели — без скролла на 360 px; каталог/заказы/аналитика — на 768 и 1280 тоже. **Найдено и исправлено:** `/admin/catalog` на 360 px раздувался до 644 px из-за `select` категории с длинными названиями (`.adm-field` в сетке без `min-width:0`) — тест `tests/a11y/admin-layout.test.ts`, повторный замер 360/360.
- **Клавиатура** (реальное нажатие Tab, затем программный обход всех фокусируемых элементов, проверка видимого контура и доступного имени): главная (54 элемента), раздел каталога (485), карточка товара (107) — у всех есть видимый фокус и имя, `tabindex > 0` нет, первый Tab попадает в «Перейти к содержимому», один `h1`, у всех изображений есть `alt`, `lang="ru"`. Корзина и оформление: реальное нажатие Tab не удалось (браузер не успел отрисовать), общее правило `:focus-visible` и разметка те же, но отдельным проходом они не подтверждены.
- Админка: страницы открыты и измерены, отдельный клавиатурный проход не делался.
- Скринридеры и реальные телефоны не проверялись.

## Найдено и исправлено при проверке

1. `instrumentation` отсутствовал: журнал платежей не писался, почта не подключалась, «популярные» были по алфавиту. Добавлено `src/instrumentation.ts` + `src/server/startup.ts`; состояния (очередь писем, популярность, журнал платежей) вынесены на `globalThis`, иначе разные бандлы Next.js их не видят.
2. Сбой обмена с 1С не отправлял письмо администратору — теперь `integration.failed`.
3. Фокус на тёмном подвале (контраст < 3:1) — исправлено.
4. `/admin/catalog` на 360 px — исправлено.
5. `.env.example` содержал `ADMIN_PASSWORD=Admin` — значение убрано; добавлены недостающие имена (`NEXT_DIST_DIR`, `APP_ENV`, `HTTPS_REDIRECT`).
6. ESLint проверял папки сборок `.next*` и песочницу — добавлено в игнор.
