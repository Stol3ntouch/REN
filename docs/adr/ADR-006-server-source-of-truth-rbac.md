# ADR-006: Сервер как источник истины цен и прав, проверка прав внутри обработчика

## Контекст
Бриф требует серверной проверки цен, доступности, количества и прав на каждое действие. В админке две роли, admin и manager, с разной матрицей.

## Решение
Цены, наличие, суммы и скидки пересчитываются на сервере из базы; значения из запроса игнорируются, а при расхождении с корзиной покупатель видит список изменений, и заказ не создаётся. Права задаются списком разрешений на роль. Каждый серверный обработчик и server action вызывает проверку права внутри себя, не полагаясь на навигацию или layout. Чужие ресурсы отвечают 404, а не 403.

## Почему
- Проверка прав только в middleware или layout отвергнута: server action и прямой запрос её обходят, а у layout здесь нет редиректа.
- Доверять цене из корзины клиента отвергнуто: подмена в запросе меняет сумму заказа.
- Ответ 403 на чужой заказ отвергнут: подтверждает, что такой номер существует, и открывает перебор.

## Последствия
- Каждая новая защищённая операция обязана содержать явный вызов проверки; забытый вызов не ловится компилятором, поэтому нужен тест на каждую операцию.
- Страницы админки защищаются отдельно первой строкой; забыть её значит открыть страницу.
- Права укрупнены (15 разрешений): отдельную роль под контент-менеджера придётся вводить правкой матрицы и кода.
- Расхождение цены останавливает оформление, из-за чего покупателю иногда приходится подтверждать заказ повторно.
