# ADR-001. Стек: Next.js + TypeScript + SQLite (`node:sqlite`)

Статус: принято (T01, 2026-10-22).

## Контекст

Нужен интернет-магазин на русском: каталог из YML (1218 товаров, 185 категорий), корзина и заказ, админка, SEO, почта, позже 1С. Локальный запуск на Windows без Open Server, PostgreSQL и Docker (на машине их нет).

## Решение

Модульный монолит: Next.js (App Router, серверный рендер) + TypeScript strict. БД — SQLite через встроенный `node:sqlite`. Только npm, `package-lock.json` не удалять.

Проверено на этой машине (Windows 11, Node 26.12.1, npm 12.2.1):

Замечание про npm 12: он по умолчанию блокирует скрипты установки (`esbuild`, `unrs-resolver`). Это ничему не мешает — `tsx`, `vitest`, `sharp` и ESLint работают; в `npm install` остаются предупреждения, одобрять скрипты не нужно.

## Отклонение от PostgreSQL

Брифинг предлагал PostgreSQL. Берём SQLite, потому что:

- на машине нет ни PostgreSQL, ни Docker, а требование — запуск одной командой;
- 1218 товаров и один склад — нагрузка на порядки ниже пределов SQLite;
- резервная копия — один файл (WAL, онлайн-бэкап), нет отдельного сервера для обслуживания;
- SQL изолирован в `src/server/db/**` (репозитории), миграции — обычные файлы `migrations/NNNN_*.sql`, ORM не привязывает к диалекту.

Условия пересмотра (переезд на PostgreSQL): несколько экземпляров приложения за балансировщиком; устойчивая запись из нескольких процессов с конкуренцией, при которой `BEGIN IMMEDIATE` и `busy_timeout` дают заметные задержки; размер БД или каталога, при котором FTS5-поиск перестаёт укладываться в бюджет; требование хостинга или 1С-интеграции к внешней СУБД. При переезде переписываются репозитории и SQL-диалект миграций; доменный код не меняется.

## Следствия

- `node:sqlite` синхронный: репозитории и `withTransaction` синхронны, не держите транзакцию открытой на `await`. Домены могут оставаться `async`.
- Соединение одно на процесс (`getDb()`), в dev живёт на `globalThis` и переживает горячую перезагрузку; при первом обращении применяются миграции.
- Лимитер запросов хранится в БД (таблица `rate_limit`, фиксированное окно): счётчики общие для процессов и переживают перезапуск; цена — одна запись в SQLite на проверку, для форм магазина это приемлемо.
- На Windows файловая система не различает регистр: не заводите файлы, отличающиеся только регистром (`placeholder.ts` и `Placeholder.tsx` ломают импорт).
