# ADR-005: Единая точка смены статуса заказа и таблица переходов

## Контекст
У заказа десять статусов, менять их могут сотрудники, покупатель, webhook оплаты и обмен с 1С. Деньги и возвраты привязаны к статусам.

## Решение
Статус меняется только функцией перехода. Допустимые переходы заданы одной таблицей; недопустимый отказывает. Автор перехода (сотрудник, система, покупатель) фиксируется в событии заказа. «Оплачен» и «ошибка оплаты» ставит только система по проверенному webhook. «Возврат» возможен только для оплаченного заказа и только от admin. Оплаченный заказ нельзя отменить, только вернуть.

## Почему
- Прямое обновление поля статуса из каждого обработчика отвергнуто: правила разъезжаются, а аудит и письма пропускаются.
- Свободный граф переходов отвергнут: тогда webhook или 1С могут вернуть доставленный заказ в «новый».
- Разрешить 1С менять оплату отвергнуто: источник истины об оплате наш webhook, из 1С принимаются только статусы исполнения.

## Последствия
- Любое новое состояние или канал (новая служба доставки) требует правки таблицы и тестов; это дорого по замыслу.
- Опоздавший webhook по отменённому заказу заказ не меняет, а превращается в предупреждение «нужен возврат» для человека.
- Повторный переход в тот же статус даёт ошибку конфликта, и вызывающий обязан проверять статус заранее.
- Статусы жёстко прошиты в аналитике (какие считаются «неотменёнными»).
