# ADR-015. Продажи: статусы заказов, возврат на шаг, обращения и ремонт

Статус: принято (C09). Дополняет ADR-005 (единая точка смены статуса).

## Статусы заказа: новые названия, старые коды

Бизнес-процесс по ТЗ: Новый, Подтверждён, Собирается, Передан в доставку, Выполнен, Отменён. Коды в БД и в коде **не переименовывались**
(их читают оплата, аналитика, 1С, кабинет покупателя), поэтому сопоставление такое:

| Код | Название в интерфейсе |
|-----|----------------------|
| `new` | Новый |
| `confirmed` (новый, миграция 1400) | Подтверждён |
| `processing` | Собирается (раньше «В обработке») |
| `shipped` | Передан в доставку (раньше «Отправлен») |
| `ready_for_pickup` | Готов к выдаче |
| `delivered` | Выполнен (раньше «Выдан / доставлен») |
| `cancelled` | Отменён |
| `awaiting_payment`, `paid`, `payment_failed`, `refunded` | технические статусы онлайн-оплаты, без изменений |

Данные заказов не менялись; миграция 1400 лишь пересоздала `orders` с более широким CHECK (дочерние строки, платежи, журнал
webhook и выгрузки в 1С сохраняются, это проверено тестом на БД «до C09»).

## Возврат на предыдущий шаг

`REVERSE_TRANSITIONS` (status.ts) — явная таблица: Подтверждён → Новый, Собирается → Подтверждён, Передан в доставку / Готов к выдаче → Собирается,
Выполнен → Передан в доставку / Готов к выдаче, Отменён → Новый / Ожидает оплаты. Возврат идёт через `orders.transition(..., { revert: true })`:
причина обязательна, пишется событие `revert` и аудит `order.revert`, история не удаляется. Из «Выполнен» и «Отменён» возвращает только
право `orders.refund`. Оплата и «возврат средств» назад не идут. Возврат из «Отменён» снова занимает использование купона.

## Оплата

Статус оплаты ставится только проверенным webhook. Административный путь — «Отметить оплаченным» для оплаты при получении / вне системы:
право `orders.write`, явное подтверждение и комментарий, событие `payment.manual`, аудит; статус заказа не меняется. Онлайн-оплату так отметить нельзя.
Возврат средств — право `orders.refund` и подключённый провайдер; иначе в карточке честная надпись «не подключено».

## Остатки

Резерв и списание делает сервис остатков C04 (ADR-014) из `checkout.place` и `orders.transition`; он идемпотентен по `stock_movements`.
Возврат заказа на шаг назад складские остатки **не трогает** (оператор корректирует их вручную, как и описано в ADR-014).
Таблица `order_stock_effects` создана миграцией 1400, но не используется (оставлена, чтобы не менять применённую миграцию).

## Обращения и ремонт

Один поток `requests`, два набора статусов (миграция 1420): обращения — new / in_work / waiting / closed; ремонт — new / diagnostics / awaiting_approval /
in_repair / awaiting_parts / ready / completed / cancelled с таблицей переходов (workflow.ts). Старые значения: у обращений done и cancelled стали closed,
у ремонта in_work → diagnostics, done → completed. Прежний `requestsAdmin.update` принимает `done` как псевдоним.
История — `request_events`, внутренние комментарии — `request_comments`, фото ремонта (до 5) — `request_photos` + `src/media`.
Фото с публичной формы догружаются отдельным запросом по подписи (HMAC от номера), выданной в ответе формы, в течение часа.

## Персональные данные

Роли, которые только читают заказы (склад: `orders.read` без `orders.write` и `customers.read`), видят телефон и email замаскированными
(список, карточка, печать, CSV). В аудит значения имён, адресов, телефонов и email не попадают — только перечень изменённых полей.
