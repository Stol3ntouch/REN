# ADR-010: Тестовая оплата только вне production, «оплачен» только по подписанному webhook

## Контекст
Провайдер эквайринга не выбран. Бриф запрещает фиктивную production-оплату, но поток оплаты нужно проверить целиком.

## Решение
Есть тестовый провайдер со страницей «ТЕСТОВАЯ ОПЛАТА» и способом оплаты «онлайн (ТЕСТ)». В production он не создаётся, не принимается и страница отвечает 404. Статус «оплачен» ставится только по webhook с подписью HMAC, при совпадении суммы, валюты RUB и заказа; возврат браузера покупателя оплатой не считается. Карточные данные не хранятся.

## Почему
- Ставить «оплачен» по возврату покупателя на сайт отвергнуто: адрес возврата открывается вручную, и заказ окажется оплаченным без денег.
- Оставить тестовый способ включаемым флагом в production отвергнуто: одна ошибка настройки открывает бесплатные заказы.
- Не делать тест оплаты вовсе отвергнуто: сценарии успеха, отказа, повтора, неверной подписи и несовпадения суммы нечем проверять.

## Последствия
- Подключение реального провайдера всё равно потребует новой проверки подписи и новой страницы, проверенными окажутся лишь общие части потока.
- Опасно оставлять включённый тестовый способ в окружении, похожем на production, но не названном им: определение production лежит в двух местах, и тест сверяет их.
- Пустой секрет подписи вне production заменяется случайным на процесс, поэтому после перезапуска старые тестовые webhook не пройдут.
- Заказ с итогом 0 ₽ проводится системой без платежа.
