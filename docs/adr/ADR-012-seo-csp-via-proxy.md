# ADR-012: HTTPS-редирект, CSP и noindex в одном proxy

## Контекст
Нужны HTTPS-редирект, HSTS, защитные заголовки и запрет индексации служебных страниц. Пути служебных страниц разбросаны по приложению. Приложение разворачивается за реверс-прокси.

## Решение
Заголовки безопасности и noindex ставит один слой proxy Next. CSP строится одной функцией с nonce для скриптов, список разрешённых источников хранится в одном файле. Редирект на HTTPS ориентируется на заголовок схемы от реверс-прокси; health-проверка из него исключена. Метаданные страниц (canonical, Open Graph, JSON-LD) собираются из общих функций SEO.

## Почему
- Заголовки на каждой странице отвергнуты: легко забыть закрытый раздел, и noindex вместе с CSP разъезжаются.
- Статичный CSP без nonce отвергнут: потребовал бы разрешить inline-скрипты и обессмыслил защиту.
- Строить CSP на самом реверс-прокси отвергнуто: nonce генерируется на запрос приложением.

## Последствия
- За реверс-прокси в production обязателен заголовок протокола https, иначе получится бесконечный редирект. Это ловушка при каждом новом деплое.
- Nonce делает страницы динамическими, и их нельзя полностью кэшировать статически.
- Каждый новый внешний источник скриптов, картинок или карт требует правки файла CSP и теста, иначе браузер молча его заблокирует.
- Разметка и noindex зависят от списка путей; новый закрытый раздел нужно добавить туда.
- Туннели для показа требуют переключателя, отключающего редирект.
