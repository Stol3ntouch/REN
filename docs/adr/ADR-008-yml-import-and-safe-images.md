# ADR-008: Импорт YML с предпросмотром и скачивание картинок по allowlist

## Контекст
Каталог приходит из чужого фида (1218 товаров, до 25 картинок на товар). Ссылки на картинки берутся из недоверенного файла, который загружает сотрудник.

## Решение
Импорт идёт в три шага: разбор, план без записи (создано, обновится, пропущено, ошибки), применение после подтверждения. Товары, которых нет в файле, не удаляются. Картинки скачиваются только по http(s) с разрешённых хостов; после DNS-резолва блокируются частные, loopback и link-local адреса, редиректы на чужие хосты запрещены, заданы лимиты размера и времени. Файл перекодируется, имя случайное, EXIF удалён.

## Почему
- Скачивать любую ссылку из фида отвергнуто: это прямой SSRF в локальную сеть и облачные метаданные.
- Проверять только имя хоста из URL отвергнуто: имя может резолвиться во внутренний адрес, поэтому проверяется адрес после резолва.
- Применять файл сразу отвергнуто: ошибка в фиде тихо испортит живой каталог.
- Удалять отсутствующее в файле отвергнуто: усечённый или неполный фид уничтожит товары, а заказы ссылаются на них.

## Последствия
- Отозванный из фида товар остаётся на витрине, пока его не скрыли вручную.
- Новый источник картинок требует явного добавления хоста в allowlist.
- Перекодирование зависит от библиотеки обработки; если она не встала, сохраняется проверенный оригинал, и это придётся отмечать в отчёте.
- Скачивание по реальной сети на живом хосте тестами не покрыто (тесты на подменах).
