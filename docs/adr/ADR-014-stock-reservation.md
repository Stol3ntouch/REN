# ADR-014. Остатки: учёт, резерв и списание

Статус: принято (C04).

## Контекст

В YML и от 1С приходит только признак «есть / нет» (`in_stock`), количества нет. Админке нужны остаток, резерв и история операций,
а витрине — наличие отдельно от публикации. Склады (несколько мест хранения) — отдельная задача C12.

## Решение

- `products.stock_qty` — остаток, `reserved_qty` — резерв под открытые заказы, свободно = остаток − резерв.
  БД не даёт отрицательных значений и резерва больше остатка (CHECK и триггеры).
- **Учёт включается явно** (`stock_tracked = 1`) — когда остаток впервые задан вручную. Пока он выключен, количество неизвестно,
  наличие берётся из `in_stock` импорта/1С, а заказ ничего не резервирует. Остатки не выдумываем (ADR-011).
- Остаток меняет только сервис `stock` (`src/domain/catalog/stock.ts`), в одной транзакции с записью в `stock_movements`
  (дельта, остаток после, резерв, причина — обязательна, автор, ссылка `order:<id>`).
- Наличие (`availability`: `in_stock | out_of_stock | preorder | discontinued`): по умолчанию вычисляется — при учёте
  «свободно > 0», иначе из `in_stock`; администратор может закрепить статус (`availability_manual = 1`).
  `products.in_stock` остаётся зеркалом (продаются «в наличии» и «под заказ»), чтобы корзина и витрина не менялись.
- Публикация (`published`, `hidden_by_admin`) от наличия не зависит: опубликованный товар без остатка показывается
  «нет в наличии» и в корзину не добавляется.

## Заказы

| Событие | Действие |
|---------|----------|
| оформление заказа | резерв по каждой позиции товара с учётом; не хватает свободного — оформление отклоняется (409), ничего не резервируется |
| `shipped` или `delivered` | списание: остаток и резерв уменьшаются, один раз на позицию |
| `cancelled`, `refunded` до списания | возврат резерва |
| `ready_for_pickup`, `paid`, `payment_failed` и др. | остаток не меняется |
| `refunded` после списания | остаток сам не возвращается — вернуть товар на склад можно ручной операцией |

Состояние заказа по позиции вычисляется из `stock_movements` (сумма `reserved_delta` по ссылке `order:<id>`), поэтому повторные
вызовы идемпотентны. Хук стоит в `checkout.place` и `orders.transition` (единственная точка смены статуса, ADR-005).

## Последствия

- Возврат заказа из конечного статуса (`revert`) резерв заново не ставит — оператор корректирует остаток вручную.
- Корзина не проверяет свободный остаток: проверка и резерв — при оформлении (сервер — источник истины).
- Несколько складов — C12; тогда `stock_movements` получит ссылку на склад.
