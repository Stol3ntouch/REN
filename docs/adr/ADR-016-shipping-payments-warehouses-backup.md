# ADR-016. Доставка, оплата, склады, налоги, почта, копии и интеграции (C12)

Статус: принято (C12). Дополняет ADR-010 (тестовая оплата), ADR-014 (остатки), ADR-015 (продажи).

## Секреты платежей и интеграций

**Решение: ключи и секреты живут только в окружении сервера** (`.env`, настройки хостинга). В БД их нет и колонок под них нет;
админка показывает лишь «задан / не задан» и не принимает значения секретов. Причина: зашифрованное хранилище в БД всё равно требует
главного ключа в окружении, то есть добавляет поверхность атаки без выигрыша; смена ключа — перезапуск, как и для остальных переменных.

- В интерфейс и ответы server actions секреты не попадают ни целиком, ни масками (последние символы не показываются).
- Отпечаток настроек для проверок соединения строится из несекретных значений и признака «задан + длина» для секретов.
- В аудит попадают изменённые поля, но не значения секретов и не тексты писем.
- Тесты кладут «секреты» в окружение и проверяют, что их нет в `JSON.stringify` ответов (`tests/ordering/payments.test.ts`, `tests/admin/integrations-cards.test.ts`).

## Доставка и оплата

- Расчёт на сервере при оформлении (`checkout.place`): стоимость или «рассчитает менеджер»; порог бесплатной доставки и минимальная сумма
  считаются от суммы товаров **после скидки**; география — адрес обязан содержать одно из названий (границы слов, регистр и «ё» не важны).
  Сроки — текст администратора, сайт их не вычисляет.
- Комиссия оплаты = фиксированная часть + процент (сотые доли процента) от **товары − скидка + известная доставка**; пределы min/max
  применяются к той же базе (без комиссии и налога). Комиссия хранится в заказе (`payment_fee_kopecks`) и входит в итог.
- Новый способ оплаты можно создать только «при получении»: онлайн-метод без провайдера не создаётся. Онлайн-метод без подключённого
  провайдера включить нельзя; в production запрещены тестовые методы и тестовый режим.

## Деньги, налоги и округление

Целые копейки, `src/domain/pricing/money.ts` (BigInt, отрицательные значения запрещены). Правило округления (`none|down|up|nearest`,
шаг копейка/рубль) применяется к **процентам** (комиссия, налог); `none` — это «до копейки, половина вверх» (копейка — минимальная единица).
Налог считается по каждой позиции с её цены после доли скидки (остаток от деления — последней строке); доставка и комиссия не облагаются.
«Внутри цены» налог только раскрывается, «сверху» — прибавляется к итогу. Флаг «цены включают налог» делает любую ставку включённой.
Ставок по умолчанию нет — пока ставка не назначена, налог равен нулю и итоги прежние. Правила, по которым посчитан заказ, сохраняются
в `orders.charges_json`: правка состава заказа пересчитывается по ним, а не по сегодняшним настройкам; у заказов до C12 надбавок нет.
Ограничение: ставка одна на магазин (по умолчанию); налог по товарам с разными ставками потребует поля ставки в карточке товара.

## Склады

`stock_by_warehouse(product_id, warehouse_id, qty, reserved)`, склад по умолчанию создан миграцией (адрес не придуман). Инвариант:
для товара с учётом `products.stock_qty = Σ qty` и `reserved_qty = Σ reserved`. Единственная точка записи остатка (`stockRepo.save`)
после обновления товара вызывает `warehousesRepo.reconcile`: прирост идёт на склад-цель (или по умолчанию), убыль — со склада-цели
либо со складов по порядку «по умолчанию → прочие», но не глубже свободного остатка; резерв по заказам делится так же. Перемещение между
складами — одна строка в `stock_movements` с нулевыми delta, складом-источником, получателем и `moved_qty` (сумма по товару не меняется).
Старый путь (форма товара) работает с итогом и по-прежнему допустим.

## Почта

События × получатели включаются в `email_event_settings`, свои шаблоны — в `email_templates`; нет строки — текст из `templates.ts`.
Шаблоны по умолчанию с `{переменными}` проверены тестом на совпадение с кодом. Письма сброса пароля и подтверждения email отключить
нельзя. Приветствие при регистрации (`auth.registered`) по умолчанию выключено. Тестовая отправка показывает ответ почтового сервиса;
без SMTP — «не отправлено». Тело писем и payload в журнале не показываются.

## Резервные копии

Копия — БД и загруженные файлы (`scripts/backup.ts`), экспорт товаров копией не называется. Задача `queued → running → ok|error` с
прогрессом, одна за раз; скачивание — одноразовая ссылка на 5 минут (в БД хеш токена). Восстановление: права `backup.run` + `settings.write`,
слово «ВОССТАНОВИТЬ», пароль сотрудника, проверка копии и обязательная копия «до восстановления». **Замену файла БД делает следующий
запуск приложения** (`src/instrumentation.ts` → `applyPendingRestore`) или `npm run restore -- --pending`: подменить БД у работающего
процесса безопасно нельзя. Прежнее состояние остаётся в `data/pre-restore-*`.

## Интеграции

Статусы: не настроено → настроено, не проверено → подключено (после успешной проверки порта; проверка действует 24 часа и сбрасывается
при смене настроек) | ошибка. В сборке реальную проверку умеет только почта (SMTP `verify`); платёж, доставка и 1С — заглушки, CRM и
аналитика — заготовки портов, они «подключёнными» не бывают. Ошибка проверки уходит в уведомления админки (`notify`).
