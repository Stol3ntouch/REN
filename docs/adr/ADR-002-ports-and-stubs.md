# ADR-002: Внешние системы только через порты с заглушками

## Контекст
1С, эквайринга, службы доставки и SMTP у владельца пока нет, провайдеры не выбраны. Сайт должен работать и проверяться сейчас, а реальные поставщики подключатся позже.

## Решение
Каждая внешняя система (1С, оплата, доставка, почта) описана интерфейсом-портом. У каждого порта есть локальная заглушка, реализация выбирается по env. Доменный код знает только порт. Заглушка сама сообщает, что она заглушка (`connected:false, mode:'stub'`), и админка это показывает. Каждый внешний вызов идёт с таймаутом и не более чем тремя повторами, результат пишется в журнал запусков.

## Почему
- Вызывать будущие API напрямую из домена отвергнуто: документации нет, пришлось бы угадывать контракты, а замена провайдера потребовала бы правки заказов и оплаты.
- Одна общая «интеграционная шина» отвергнута: у четырёх систем разные формы обмена (пакеты, webhook, запрос тарифа, письмо), общий интерфейс получился бы пустым.
- Скрывать заглушку от пользователя отвергнуто: бриф прямо запрещает фиктивную production-оплату и выдуманные тарифы, значит режим «не подключено» должен быть виден сотруднику.

## Последствия
- Форма порта выведена из заглушки, а не из реального API. Подключая настоящую 1С или платёжного провайдера, интерфейс почти наверняка придётся менять, причём вместе с доменным кодом.
- Заглушки нужно поддерживать и тестировать наравне с кодом.
- Часть состояния заглушек (подключение к приложению при старте) живёт отдельно от портов; если забыть подключить, журнал платежей молча не пишется.
