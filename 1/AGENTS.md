# Инструкция для Claude Code — РемТехСад

## До изменений
1. Прочитай README и все релевантные файлы `docs/`.
2. Осмотри текущий репозиторий, инструкции, структуру, зависимости, тесты, конфигурацию и `git diff`; не перезаписывай чужую работу.
3. Составь план вертикальных срезов, критерии приёмки и список блокирующих неизвестных.
4. Сравни не более трёх подходящих стеков; проверь актуальные официальные требования и совместимость с будущей 1С. Не принимай CMS за уже выбранную.

## Разработка
- Для новой бизнес-логики по возможности сначала напиши тест, затем реализацию и повторный прогон.
- Добавь README, `.env.example`, `.gitignore`, миграции и CI-проверки, если стек/среда позволяют.
- Проверяй права на сервере, не только скрытием пунктов меню.
- Не выдавай фиктивную оплату/синхронизацию за production-реализацию. До выбора провайдеров используй изолированные адаптеры и явно описанные тестовые doubles.
- Импорт, повторные запросы и webhook должны быть идемпотентными и защищёнными от дублей.
- Секреты — только в переменных окружения/secret manager. Не логируй пароли, токены, платёжные данные и лишние персональные данные.
- Не выполняй публикацию, платные закупки, изменение DNS, удаление данных или production-миграции без явного согласия.

## Проверки и отчёт
Запускай доступные тесты, lint, typecheck, build и проверки безопасности. В финале перечисли изменённые файлы, точные команды и реальные результаты; отдельно укажи непроверенные места, риски и следующий шаг. Не заявляй, что проверка прошла, если она не запускалась.
