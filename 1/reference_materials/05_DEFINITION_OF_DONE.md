# Definition of Done — критерии готовности

Задача не считается завершённой, если её результат не соответствует применимым пунктам ниже. Не все пункты нужны каждому проекту, но исключения должны быть осознанными.

## Требования и UX
- [ ] Выполнены согласованные сценарии и критерии приёмки.
- [ ] Нет кликабельных элементов, которые ничего не делают, если они не обозначены как demo/disabled.
- [ ] Есть загрузка, пустое состояние, успешный результат и понятная ошибка для основных действий.
- [ ] Формы проверяют данные на клиенте для UX и на сервере для безопасности.
- [ ] Адаптивный интерфейс проверен на основных ширинах; клавиатура и видимый фокус работают.
- [ ] Тексты ошибок не раскрывают внутреннюю информацию, но объясняют, что делать дальше.

## Код и данные
- [ ] Новая бизнес-логика покрыта подходящими тестами.
- [ ] Нет фиктивных реализаций в production-пути, если они не согласованы.
- [ ] Нет секретов и настоящих персональных данных в коде, фикстурах, истории и документах.
- [ ] Ошибки обрабатываются; опасные операции имеют права/подтверждение/откат.
- [ ] Схема БД и миграции согласованы; есть правила целостности и необходимые индексы.
- [ ] Зависимости и лицензии приемлемы; отсутствуют безосновательные пакеты.

## Проверки
- [ ] Запущены unit-тесты / компонентные тесты, если применимо.
- [ ] Запущены интеграционные тесты ключевых интеграций/БД.
- [ ] Выполнены lint, typecheck и build, если их поддерживает проект.
- [ ] Критические сценарии проверены вручную или e2e-тестами.
- [ ] Проверены отрицательные и граничные случаи.
- [ ] Результаты команд и ограничения среды отражены честно.

## Релиз и передача
- [ ] Приложение можно установить/запустить по README с чистого окружения.
- [ ] `.env.example` актуален; переменные объяснены.
- [ ] Настроены подходящие логи, health check и обработка остановки приложения.
- [ ] Документированы бэкап/восстановление и миграции, если важны данные.
- [ ] Есть инструкция деплоя, rollback и ограничения тарифов/квот.
- [ ] Описаны известные баги, риски, неработающие/непроверенные части.

## Формат итогового отчёта

1. **Статус:** готово / условно готово / не готово.
2. **Что реализовано:** по требованиям.
3. **Изменённые файлы:** пути и краткое назначение.
4. **Проверки:** точные команды и результаты. Не выполненные проверки перечислить отдельно.
5. **Запуск:** последовательность команд, переменные окружения и доступы без раскрытия секретов.
6. **Известные ограничения и риски.**
7. **Следующий шаг:** один приоритетный шаг, если он остался.
