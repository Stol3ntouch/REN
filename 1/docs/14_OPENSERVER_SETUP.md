# Open Server: пошаговая инструкция для Windows

## Важно перед стартом
Open Server предназначен для локальной разработки/тестирования, а не для постоянного production-магазина в интернете. Точные шаги зависят от версии Open Server и выбранного стека; после утверждения CMS документ надо дополнить точными версиями. Скачивайте Open Server только из официального источника проекта и проверяйте требования актуальной версии.

## Шаг 1. Определить стек
- Для 1С-Битрикс/WordPress понадобится совместимый PHP, набор расширений и СУБД.
- Для Next.js/Medusa нужен Node.js и зависимости проекта; Open Server может быть не нужен, кроме вспомогательных сервисов.
Не устанавливайте версии PHP/БД наугад — сверяйте с документацией выбранной CMS и проекта.

## Шаг 2. Подготовить Windows
1. Обновить Windows и выбрать папку разработки, например `C:\Dev\RemTechSad`.
2. Не размещать production-секреты на рабочем компьютере.
3. Не отключать Windows Firewall полностью и не открывать локальный сервер в публичную сеть.
4. Проверить, не заняты ли порты, которые потребуются серверу/БД.

## Шаг 3. Установить Open Server (только если выбранный стек требует PHP-окружение)
1. Скачать актуальную поддерживаемую сборку из официального источника.
2. Прочитать установочную инструкцию именно для этой версии.
3. Установить/распаковать в расположение, рекомендованное документацией.
4. Запустить с минимально необходимыми правами.
5. Если Windows просит разрешение Firewall, разрешать только нужный локальный сценарий; не включать ненужный публичный доступ.

## Шаг 4. Настроить PHP-проект
1. Выбрать версию PHP, СУБД и расширения, совместимые с CMS и её релизом.
2. Настроить локальный домен средствами версии Open Server; проверить, что он указывает на localhost.
3. Указать правильный document root. Если проект требует каталог `public`, не отдавать весь репозиторий веб-сервером.
4. Создать отдельную локальную БД и пользователя с правами только на эту БД. Не использовать root без пароля из приложения.
5. Скопировать `.env.example` в локальный `.env` и заполнить только тестовыми значениями.
6. Установить зависимости, выполнить миграции и seed только командами из README проекта и после проверки, что БД локальная.

## Шаг 5. Настроить Node.js-проект (если выбран он)
1. Установить поддерживаемую LTS-версию Node.js из официального источника, соответствующую требованиям проекта.
2. Использовать менеджер пакетов и lock-файл, уже выбранные проектом; не смешивать npm/pnpm/yarn.
3. Установить БД и вспомогательные сервисы по README; Open Server необязателен.
4. Создать локальный `.env` из `.env.example` и заполнить тестовыми значениями.
5. Выполнить команды установки, миграций, тестов и dev-запуска из README. Не пытаться запускать Node-приложение как обычный PHP-сайт.

## Шаг 6. Проверить запуск
1. Запустить приложение указанной в README командой.
2. Открыть адрес, который напечатал сервер/команда.
3. Проверить главную, каталог и тестовые данные.
4. Проверить вход в админку, роли администратора/менеджера и запрет чужих заказов.
5. Запустить тесты, lint, typecheck и build.
6. Убедиться, что `.env`, логи, uploads и backups исключены из Git.
7. Использовать тестовую 1С/песочницу платежей; не подключать локальный сайт к production-системам.

## Типовые ошибки
- **Порт занят:** определить процесс и безопасно решить конфликт; не менять службы наугад.
- **Локальный домен не открывается:** проверить настройки домена/hosts и состояние нужных служб согласно документации.
- **PHP-модуль отсутствует:** сверить требуемые расширения с документацией CMS.
- **БД не подключается:** проверить статус службы, порт, имя БД, пользователя и пароль.
- **Node не найден:** проверить установку и PATH, открыть новый терминал.
- **Зависимости не ставятся:** проверить версию runtime и lock-файл; не удалять lock-файл как случайный обход.

## Что Claude Code обязан уточнить после выбора стека
Точные версии runtime, расширений, СУБД и Open Server; команды установки/запуска/миграций/тестов/build; порты и службы; путь document root; процедуру чистой установки. Нельзя обещать запуск, пока он не был реально проверен.
