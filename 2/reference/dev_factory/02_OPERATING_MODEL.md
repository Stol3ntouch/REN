# Операционная модель Dev Factory

## Принцип: короткие циклы, проверяемые результаты

Каждая задача проходит цикл: **понять → спланировать → изменить → проверить → зафиксировать → передать**. Для масштабных задач выполняй цикл по одному вертикальному срезу, например «регистрация с API и тестом», а не сначала весь интерфейс, потом весь backend.

## Протокол нового проекта

1. Создать ID, например `WEB-001`; заполнить краткий бриф.
2. Определить категорию риска: низкий / средний / высокий. Высокий — платежи, чувствительные данные, безопасность, медицина, финансы, массовые рассылки, доступ к чужим системам.
3. Сформулировать MVP и критерии приёмки до выбора стека.
4. Выбрать стек и объяснить, почему он минимально достаточен.
5. Согласовать данные, роли, границы доверия, интеграции, развёртывание и стоимость владения.
6. Собрать работающий вертикальный срез; добавить автоматизированные тесты.
7. Проверить happy path, негативные сценарии, поведение при сбоях, безопасность и мобильный UI.
8. Подготовить чистый запуск с нуля по README.
9. Записать решения, ограничения, оставшиеся риски и следующий шаг.

## Когда задавать вопросы

Вопрос блокирующий, только если разные ответы ведут к принципиально разной архитектуре, правовым/безопасностным последствиям или значительной переделке. В остальных случаях выбери разумное допущение и обозначь его. Не превращай интервью в длинную анкету.

## Управление контекстом

- Одна кодовая база — один чат реализации. Независимый аудит делай в отдельном чате, чтобы он не повторял слепо решения автора.
- В начале каждого продолжения передай ID, текущее дерево файлов, последние решения, последний успешный тест и следующий шаг.
- Для долгого проекта держи `README.md`, `docs/architecture.md`, `docs/decisions/`, `CHANGELOG.md` и `AGENTS.md` в репозитории; не полагайся только на историю переписки.
- Не вставляй большие исходники в несколько чатов без необходимости: передавай файлы/патчи и краткие summaries.

## Принцип завершения

Задача закрыта не тогда, когда ответ выглядит убедительно, а когда пользовательские критерии выполнены и проверены настолько, насколько позволяет среда. Все непроверенные места перечисляются явно.
