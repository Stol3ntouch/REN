# Эквайринг

- Предусмотрен один платёжный провайдер; конкретный поставщик ещё не выбран/не переданы данные.
- Реализовать изолированный адаптер провайдера, а не смешивать его API с логикой заказа.
- Предпочитать hosted checkout/tokenization, если поддерживается; не хранить данные банковских карт.
- Статус «оплачен» устанавливается по серверному подтверждению/проверенному webhook, не по URL возврата браузера.
- Проверять подпись, ID заказа, сумму и валюту.
- Повторные webhook обрабатывать идемпотентно.
- Нужны тестовый режим и сценарии: успех, отказ, тайм-аут, повтор, неверная подпись, несовпадение суммы, возврат.
- Ключи передаются через секреты окружения. Реальные платежи включаются только после отдельной проверки и подтверждения.
