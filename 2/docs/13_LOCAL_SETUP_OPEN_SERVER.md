# Локальная разработка: Windows и Open Server

## Важное различие
Open Server допустимо рассматривать как локальную среду для разработки/демонстрации, если выбранный стек совместим. Это не автоматическая рекомендация для production. Инструкции ниже — порядок действий, а точные команды зависят от стека, который будет выбран после аудита.

## Пошаговый план
1. Установить Git и выбранные runtime/пакетный менеджер по официальной документации.
2. Установить/настроить Open Server только если архитектура требует его локального веб-сервера или PHP/MySQL-совместимой среды.
3. Распаковать проект в рабочую папку, не в публичный каталог без понимания правил сервера.
4. Скопировать `.env.example` в локальный env-файл и заполнить тестовыми значениями; не использовать production-ключи.
5. Установить зависимости точной командой из `README.md` проекта.
6. Создать локальную базу, применить миграции и тестовые seed-данные.
7. Запустить unit/integration-тесты, lint/typecheck/build — если они настроены.
8. Запустить приложение согласно выбранному стеку.
9. Проверить главную, каталог, поиск, карточку товара, корзину, тестовый заказ и вход в админку.
10. Проверить, что интеграции 1С/оплаты/доставки отключены или используют тестовые адаптеры.
11. Не публиковать локальный сервер в интернет и не использовать Open Server как production без отдельного обоснования, hardening и проверки безопасности.

## Что добавить после выбора стека
Точные версии, команды установки, настройки виртуального хоста, PHP/Node/Python, БД, HTTPS локально, пути логов и способы обновления. Нельзя корректно заполнить это до выбора CMS/framework и ОС.
