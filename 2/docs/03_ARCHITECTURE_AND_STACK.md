# Архитектура и стек

## Принципы
- Сначала проверить обязательность Bitrix/CMS и условия эксплуатации; в схеме упомянут Bitrix, но выбор платформы не утверждён.
- Для небольшого магазина предпочтителен модульный монолит, а не микросервисы без измеримой причины.
- Разделить UI, бизнес-логику, хранение данных и интеграционные адаптеры.
- Реляционная БД с миграциями, индексами, ограничениями целостности и проверяемым backup.
- Все внешние вызовы имеют тайм-ауты, обработку ошибок и ограниченные повторы.
- Секреты и адреса API — через переменные окружения/secret manager.

## Что сравнить до выбора
1. Обязательная CMS (например, Bitrix) против кастомного web-приложения.
2. Возможности SEO и редактирования контента.
3. Совместимость с 1С и фактический протокол обмена.
4. Стоимость лицензии/хостинга, сопровождение и переносимость.
5. Доступность тестов, обновлений и специалистов.

Не фиксировать конкретные версии и API до проверки официальной документации на дату реализации.
