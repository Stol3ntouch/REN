## Что должно заработать

`npm run import:yml -- <файл>` читает реальный YML (1218 товаров, 185 категорий), строит предпросмотр (создано / обновится / пропущено / ошибки), применяет его идемпотентно по `(source='yml', external_id)` и печатает отчёт. Категории (2 уровня), товары, характеристики, цены в копейках, наличие и ссылки на фото попадают в БД; изображения скачиваются безопасно (allowlist, SSRF-защита, проверка типа и размера, перекодирование, варианты размеров). Повторный импорт — ноль дублей. Товары, которых нет в файле, не удаляются. Поля из `locked_fields` импорт не перезаписывает. Функции `parseYml/planImport/applyImport` потом использует админский UI (T10).

## Из брифа, дословно

> «Нужны загрузка каталога, предпросмотр и отчёт ошибок. Excel/CSV/XML могут быть вариантами после согласования формата»
> «Повтор импорта не создаёт дубликаты товаров/категорий»
> «Для URL изображений использовать allowlist/защиту от SSRF; не разрешать доступ к localhost и внутренним сетям»
> «Сжатие/изменение размеров загружаемых изображений и проверка типа/размера»

## Критерии приёмки

- [ ] Импорт полного `catalog.yml` создаёт 185 категорий и 1218 товаров; артикул = `model`; цена в копейках; `available=false` → «нет в наличии»
- [ ] Второй запуск того же файла: 0 создано, 0 изменено, 0 дублей (тест)
- [ ] Товар, исчезнувший из файла, остаётся в БД (тест); поле из `locked_fields` не перезаписывается (тест)
- [ ] Битая строка, неизвестная категория, пустая цена попадают в отчёт ошибок, остальные строки применяются; не-XML файл или >20 МБ отклоняется
- [ ] `safeFetchImage` отклоняет хост вне allowlist, `localhost`, `127.0.0.1`, `10.*`, `169.254.*`, `[::1]`, редирект на внутренний адрес, ответ >5 МБ и не-изображение (тесты с поддельным резолвером)
- [ ] `storeImage` проверяет сигнатуру файла (не расширение), даёт случайное имя и варианты размеров (или документированный fallback без `sharp`); «jpg» с HTML внутри отклоняется
- [ ] Сбой скачивания фото не блокирует импорт: он попадает в отчёт, товар создаётся
