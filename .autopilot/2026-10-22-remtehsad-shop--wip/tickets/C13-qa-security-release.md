# C13 — Безопасность, адаптив, производительность, E2E, документы

**Требования:** G12, G54, G55, G56, G57
**Зависит от:** C02, C03, C04, C05, C06, C07, C08, C09, C10, C11, C12
**Зона:** `tests/e2e/**` · `tests/a11y/**` · `tests/security/**` · `docs/**` · `README.md` · `.autopilot/PROGRESS.md` не трогать · `src/ui/admin/admin.css` (адаптивные правки) · `src/ui/admin/nav.ts` · `.env.example` (только имена) · `package.json` (скрипты e2e) · `scripts/e2e-admin.ts`
**Волна:** 18
**Ревью:** нет
**Модель:** сильная

## Что должно заработать

Админка проверена как целое: каждый пункт меню открывается, ключевые сценарии проходят на изолированной БД, права соблюдаются, адаптив и производительность в норме, документы описывают новую CMS. Исправляются найденные дефекты.

## Из брифа, дословно

> «Не считай проект полностью готовым только потому, что все страницы визуально присутствуют»
> «Все тесты должны работать в изолированном тестовом окружении и не затрагивать реальные данные. Не утверждай, что тесты прошли, если они не запускались»
> «Не переноси известные блокирующие ошибки на следующий этап без фиксации и обоснования»

## Разделы спецификации

§88 (C13); критерии завершения брифа 2026-10-24 (раздел 32).

## Критерии приёмки

- [ ] **Все пункты меню**: тест перечисляет `ADMIN_NAV`, под ролью admin/super_admin открывает каждый маршрут (200, без «Раздел в разработке», без ошибок консоли/сервера) и проверяет, что каждый `page.tsx`/`route.ts`/`actions.ts` админки защищён (расширение `admin-guards-fs.test.ts`); под ролями manager, content_manager, warehouse, service пункты без права скрыты, а прямые запросы → 403/редирект (матрица ролей × страницы, генерируется из `ROLE_PERMISSIONS`)
- [ ] **E2E-сценарии** (изолированная БД и порт, без сети; через `scripts/e2e-admin.ts` и/или интеграционные тесты route handlers/server actions, Playwright — только если уже доступен без установки браузеров, иначе реальные HTTP-запросы к собственному серверу на копии БД): 1) вход администратора; 2) создание товара с брендом, категориями, характеристиками, изображением; 3) создание категории; 4) назначение товара категории; 5) скрытие категории — товар/URL пропали на витрине, состояние сохранилось после перезагрузки; 6) правка SEO и вкладки «Дополнительно» категории; 7) изменение настроек магазина (название, телефон, переключатель «показывать цены») и проверка на витрине; 8) заказ гостя → обработка в админке (подтверждён → собирается → передан → выполнен, возврат на шаг назад, история); 9) импорт CSV с предпросмотром и сопоставлением; 10) пользователь без права не выполняет запрещённую операцию (403 и отсутствие изменений в БД); плюс создание роли с урезанными правами и проверка её действия
- [ ] **Безопасность**: проход чек-листа раздела 22 брифа с автотестами там, где возможно: CSRF/Origin на всех мутациях, rate limit входа и чувствительных действий, загрузки (подмена MIME/расширения, HTML внутри «jpg», SVG со скриптом, огромный файл, путь `../`), XSS (поля страниц, баннеров, отзывов, комментариев, названий товаров в админке и на витрине), SQL-инъекции в поиске/фильтрах/сортировке (белый список колонок), IDOR (чужие заказы, клиенты, файлы экспорта/бэкапа), приватные скачивания (экспорт, бэкап — только по праву и одноразовой ссылке), секреты не в ответах/логах (grep ответов, `payments` настройки), сессии (завершение при блокировке, смена пароля), ошибки production без деталей; найденное чинится или фиксируется в `docs/security.md` как известное ограничение с причиной
- [ ] **Адаптив и доступность**: проверка админки на 360/768/1024/1440 px без горизонтального скролла страницы (таблицы — внутренняя прокрутка/карточки), выдвижное меню, формы в одну колонку, кнопки не обрезаны, переключатели ≥44 px на телефоне; клавиатурный проход по меню/таблице/модалке/вкладкам, фокус-ловушки, `aria-live` тостов, контраст ключевых элементов ≥4.5:1 (скрипт по токенам `admin.css`), JS-бюджет публичных страниц не вырос (`npm run a11y:live` ≤200 КБ gzip)
- [ ] **Производительность**: замеры на 1214 товарах — список товаров, дерево категорий, dashboard, поиск, фильтры витрины (число SQL-запросов и время в тесте с порогами), отсутствие N+1 (тест-счётчик), индексы проверены `EXPLAIN QUERY PLAN` для основных запросов; результаты — в `docs/qa-report.md`
- [ ] **Документация**: обновить `docs/architecture.md`, `docs/security.md`, `docs/env.md`, `docs/backup-restore.md`, `docs/handoff.md`, `README.md` (новые разделы CMS, роли и права, как создать суперадмина `npm run admin:create`, настройки, импорт/экспорт, бэкап из UI), `docs/admin-guide.md` (руководство для владельца: что где в админке, как скрыть товар/категорию/страницу, как менять роли), `docs/qa-report.md` (какие команды реально запускались и результаты, что НЕ проверено), список миграций 1100+, API (`/admin/api/*`) — таблица маршрутов и прав; ADR по: правам в БД, модели остатков и резерва, хранению секретов платежей, скрытию/видимости категорий
- [ ] **Итог**: `npm run check` (все тесты, типы, линтер зелёные), `npm run build` (NEXT_DIST_DIR=.next-c13), `npm run e2e:live`/`a11y:live` на собственном сервере (порт 4600+ на копии БД) — точные числа; список оставшихся проблем с причинами; никаких TODO/пустых обработчиков/«Раздел в разработке» (grep-тест); сид ролей идемпотентен; миграции проходят на копии рабочей БД (`data/rts.sqlite`) без потери данных (тест на копии)
- [ ] Обновление песочницы: подготовить пошаговую команду для пользователя (push в `github.com/Stol3ntouch/REN`) и команды обновления внутри песочницы (`git pull`, `npm ci`, `npm run build`, `npm run db:migrate`, перезапуск) в `docs/hosting.md` (раздел «Обновление песочницы Vercel»); сама отправка кода во внешний репозиторий выполняется пользователем
