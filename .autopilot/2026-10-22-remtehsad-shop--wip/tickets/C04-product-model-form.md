# C04 — Товар: модель данных, форма, CRUD, остатки

**Требования:** G17, G19
**Зависит от:** C01, C02, C03
**Зона:** `src/domain/catalog/{products-admin,stock}.ts` · `src/server/db/repositories/{products-admin,product-categories,stock,product-media}.ts` · `migrations/1200-1249` · `src/app/admin/(panel)/catalog/products/**` · `src/app/admin/(panel)/catalog/[id]/**` · `src/app/admin/(panel)/_lib/{product,stock}-ops.ts` · `src/domain/catalog/{store,product,search}.ts` (чтение новых полей) · `src/ui/catalog/{PriceBlock,ProductCard,ProductGallery}.tsx` · `src/app/(shop)/product/**` · `src/importing/yml/apply.ts` (защита новых полей) · `tests/admin/product*.test.ts*` · `tests/catalog/**`
**Волна:** 15
**Ревью:** нет
**Модель:** сильная

## Что должно заработать

Полноценная карточка товара в админке: создание, просмотр, редактирование, публикация, удаление с проверкой зависимостей. Расширенная модель товара (старая цена, закупочная с ограничением доступа, остаток и резерв, штрихкод, бренд, несколько категорий, характеристики, галерея, флаги новинка/рекомендуемый/акционный, SEO, canonical). Отдельно наличие и публикация; изменения остатка пишутся в историю операций.

## Из брифа, дословно

> «Реализуй полный CRUD для товаров: создание, просмотр, редактирование, публикация и удаление с соблюдением зависимостей»
> «Закупочная цена с ограничением доступа»
> «Разделяй наличие товара и его публикацию… Не допускай неконтролируемого отрицательного остатка… Изменения остатков должны записываться в историю операций»

## Разделы спецификации

§88 (C04), правило денег в копейках, locked_fields импорта.

## Критерии приёмки

- [ ] Миграция расширяет `products`: `barcode, short_description, old_price_kopecks, purchase_price_kopecks (NULL), stock_qty (целое ≥0), reserved_qty (≥0), availability ('in_stock'|'out_of_stock'|'preorder'|'discontinued' — вычисляется по умолчанию из qty, но может быть задан), brand_id (из C03), is_new, is_featured (есть `featured`), is_promo, canonical_url, indexable, created_at/updated_at, created_by`; таблица `product_categories(product_id, category_id, is_primary, sort)` (основная категория дублируется в `products.category_id` для совместимости; все товары мигрируют с одной основной); `stock_movements(id, product_id, delta, qty_after, reason, ref, staff_id, created_at)`; индексы на `sku`, `barcode`, `brand_id`, `(published, hidden_by_admin)`, `(category_id)`; существующие данные импорта сохранены, `in_stock` остаётся и приводится к `availability` без потерь
- [ ] `/admin/catalog/products/new` и `/admin/catalog/<id>` (форма с `Tabs`: Основное, Цены и склад, Категории и бренд, Характеристики, Изображения, SEO): название, уникальный slug (автогенерация транслитом, проверка уникальности на сервере), SKU (уникален в рамках источника), штрихкод, краткое и полное описание (полное — через санитайзер, как в импорте), цена, старая цена (> цены, иначе ошибка), закупочная цена, остаток и резерв (резерв ≤ остатка), статус наличия, бренд, одна основная и несколько дополнительных категорий, характеристики по определениям из C03 (проверка типа/обязательности/допустимых значений), публикация и скрытие, флаги новинка/рекомендуемый/акционный, SEO Title/Meta Description/canonical/индексация; даты создания/изменения показаны; `SaveBar`, `UnsavedChangesGuard`
- [ ] **Закупочная цена**: поле видно и сохраняется только при праве `products.cost` (до C02-ключей — только admin), у остальных ни в форме, ни в списках, ни в экспорте, ни в ответах; тест на утечку (manager не получает значение ни одним путём)
- [ ] **Изображения**: загрузка нескольких файлов (JPG/PNG/WebP, проверка сигнатуры, размер, случайные имена, варианты размеров через `src/media`), главное изображение, порядок (перетаскиванием/кнопками), alt, удаление; внешние ссылки импорта (champion.ru) сохраняются и отображаются как раньше; галерея на витрине использует новый порядок
- [ ] **Остатки**: изменение остатка только через сервис `stock.adjust(productId, delta|set, reason, staff)` в транзакции с записью в `stock_movements` (причина обязательна, остаток не уходит <0, резерв не превышает остаток); публикация не зависит от остатка (опубликованный товар без остатка показывается «нет в наличии» и не добавляется в корзину); заказ (T05) уменьшает/резервирует остаток согласно простой модели: резерв при оформлении, списание при «передан в доставку/выполнен», возврат резерва при отмене — решение зафиксировать в `docs/adr/` и тестами; история операций показана на вкладке «Цены и склад»; тесты на все ветки
- [ ] Удаление товара: запрещено при наличии заказов (предложить скрыть/архивировать; снимки в `order_items` не ломаются), разрешено без заказов с ConfirmDialog; удаляет связи (категории, характеристики, изображения, избранное, корзины), в аудите — `product.delete`; копия правки пишется в аудит с до/после без закупочной для пользователей без права
- [ ] Витрина использует новые поля без регресса: старая цена и скидка («−N %» только при реальной старой цене > цены), бейджи «Новинка/Акция» по флагам, наличие по `availability`, категории множественные (товар виден в дополнительных категориях и считается в счётчиках), canonical/indexable в метаданных; sitemap/JSON-LD учитывают `indexable`
- [ ] Импорт YML не затирает поля, правленные вручную (locked_fields расширен: brand, barcode, old_price, flags и т. д.); повторный импорт идемпотентен; право `catalog.write`/`products.write` (admin), manager — просмотр; Origin, zod, аудит; существующие тесты зелёные
- [ ] `npm run check` и `npm run build` (NEXT_DIST_DIR=.next-c04) зелёные
