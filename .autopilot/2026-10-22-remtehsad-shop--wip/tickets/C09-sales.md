# C09 — Продажи: заказы, клиенты, обращения, заявки на ремонт

**Требования:** G29, G30, G31, G38
**Зависит от:** C01, C02
**Зона:** `src/domain/ordering/**` · `src/domain/customers/**` · `src/domain/requests/**` · `src/server/db/repositories/{orders,order-comments,customers-admin,customer-notes,requests,request-comments,repairs}.ts` · `migrations/1400-1449` · `src/app/admin/(panel)/{orders,customers,inquiries,repairs,requests,questions}/**` · `src/app/admin/api/{orders,customers,inquiries,repairs}/**` · `src/app/(shop)/order/**` · `src/integrations/mail/templates.ts` · `tests/ordering/**` · `tests/requests/**` · `tests/admin/{orders,customers,inquiries,repairs}*.test.ts*`
**Волна:** 15
**Ревью:** да — заказы и деньги
**Модель:** сильная

## Что должно заработать

Рабочие разделы продаж с историей, комментариями, назначением ответственных, фильтрами и уведомлениями: заказы (статусы бизнес-процесса, возврат на шаг назад, печать, экспорт), клиенты (комментарий менеджера, статус, согласия, история покупок), обращения (статусы и переписка/события), заявки на ремонт (бренд, модель, фото, статусы диагностики и ремонта).

## Из брифа, дословно

> «Учитывай ситуации, когда нужно вернуть заказ в предыдущий статус или исправить ошибку, не уничтожая историю»
> «Не имитируй успешную оплату. Статус оплаты меняется только на основании подтверждённого платёжного события или разрешённого административного процесса»
> «Разграничь доступ к персональным данным по ролям. Не показывай пароли, токены или другие секреты пользователей»
> «Статусы: новое, в работе, ожидает ответа, закрыто»
> «Примеры статусов: новая, диагностика, ожидает согласования, в ремонте, ожидает запчасти, готова к выдаче, завершена, отменена»

## Разделы спецификации

§88 (C09); существующий конвейер заказов (T05/T06: `orders.transition`, `order_events`).

## Критерии приёмки

- [ ] **Заказы** (`/admin/orders`): серверный список (поиск по номеру/имени/телефону/email, статус выполнения, статус оплаты, способ доставки/оплаты, период, ответственный, сумма; сортировка, пагинация 20/50/100), экспорт отфильтрованного CSV (`export.run`), карточка заказа: номер, клиент и контакты, состав (название, артикул, цена, скидка, количество, сумма — снимки), количество, цена товаров, скидка/купон, доставка, итог (копейки без float), способ и адрес/пункт, способ и статус оплаты, комментарий клиента, внутренний комментарий (отдельные записи `order_comments` с автором и временем, не виден клиенту), история изменений (`order_events` с автором), дата
- [ ] **Статусы** выполнения: Новый, Подтверждён, Собирается, Передан в доставку, Выполнен, Отменён (+существующие технические сохраняются/сопоставляются; миграция сопоставления старых статусов без потери данных, перенос зафиксирован в ADR); таблица допустимых переходов — единая точка `orders.transition`; **возврат на предыдущий шаг** разрешён по явной таблице (например «Собирается → Подтверждён», «Передан в доставку → Собирается») с обязательной причиной и записью события, история не удаляется; «Выполнен/Отменён» возвращаются только правом `orders.refund`/admin с причиной; тест на все пары
- [ ] Редактирование разрешённых данных до отгрузки (контакты, адрес доставки, комментарии; состав и суммы — только через явное «изменить состав» с пересчётом на сервере по снимкам цен и проверкой остатка, с записью события; запрещено после «Передан в доставку»); печать заказа (`/admin/orders/<номер>/print` — страница для печати без админского каркаса: номер, дата, клиент, состав, итоги, реквизиты магазина из настроек или метки), формирование документа (HTML для печати/PDF средствами браузера, без выдуманных реквизитов)
- [ ] Оплата: статус оплаты меняется ТОЛЬКО по проверенному webhook или явным административным действием «Отметить оплаченным (оплата при получении/вне системы)» с правом `orders.write`+подтверждением и обязательным комментарием (событие `payment.manual`, в аудите); возврат средств — только `orders.refund` через существующий платёжный порт; без подключённого провайдера кнопки возврата нет, а статус честно «не подключено»; уведомления клиенту о смене статуса — через почтовую очередь, если почта настроена, иначе видно «письмо в очереди»
- [ ] Остатки и резерв: переходы заказа вызывают сервис остатков из C04 (резерв при оформлении, списание по выбранной модели, возврат при отмене) идемпотентно; тест двойной отмены/повтора
- [ ] **Клиенты** (`/admin/customers`): список (имя, телефон, email, дата регистрации, число заказов, сумма покупок, статус клиента), поиск/фильтры (статус, период регистрации, есть заказы)/сортировки/пагинация, страница клиента: профиль, адреса, согласия (из `consents`), история заказов, сумма, комментарий менеджера (заметки `customer_notes` с автором и временем), статус клиента (`active|blocked|vip|…` из фиксированного списка; блокировка клиента запрещает вход и оформление), экспорт; пароли, токены, хеши не отображаются нигде; телефон/email по ролям: без `customers.read` нет раздела, без `customers.write` нельзя менять статус/заметки (маскирование ПДн для ролей без права — тест)
- [ ] **Обращения** (`/admin/inquiries`): объединённый список входящих (обратная связь, вопросы о товарах, звонки) с полями тема, имя, контакты, текст, дата, канал (`contact|question|callback`), статус `new|in_work|waiting|closed` (миграция добавляет `waiting`, пересоздание CHECK), ответственный (выбор сотрудника), комментарии сотрудников и история событий (`request_events`), фильтры и поиск, массовое назначение/закрытие; права `inquiries.read/write`; новое обращение создаёт уведомление `notify()`
- [ ] **Заявки на ремонт** (`/admin/repairs`): номер, клиент, телефон, email, тип техники, бренд, модель (новые поля формы заявки на сайте + админская правка), описание неисправности, фото (до 5, JPG/PNG/WebP через `src/media`, видны в карточке; форма на сайте принимает фото с проверкой содержимого и лимитом), дата поступления, ответственный, статусы: новая, диагностика, ожидает согласования, в ремонте, ожидает запчасти, готова к выдаче, завершена, отменена (допустимые переходы), комментарии и история обработки, поиск/сортировка/фильтры/назначение; уведомление `notify()` о новой заявке; письмо клиенту о смене статуса — через очередь при наличии email
- [ ] Права: `orders.read/write/refund`, `customers.read/write`, `inquiries.read/write`, `repair.write` (после C02) — прямые запросы без права → 403 (тесты по каждому ops), чужие id → 404, Origin, zod, аудит всех изменений (до/после без ПДн в открытом виде); `npm run check` и `npm run build` (NEXT_DIST_DIR=.next-c09) зелёные
