## Что должно заработать

Страница «Настройки магазина» по образцу `inputs/reference/admin-store-settings.jpg` (вкладки и карточки), хранение в базе и реальное применение на витрине, включая переключатели, которые действительно ограничивают сайт. Раздел SEO и метаданных с шаблонами и влиянием на публичные страницы.

## Из брифа, дословно

> «Реализуй серверную проверку этих настроек. Например, выключение публичного магазина должно действительно ограничивать доступ к пользовательской части в соответствии с выбранной политикой»
> «Загрузку файлов проводи через защищённый механизм хранения медиа»
> «Все настройки должны влиять на публичные страницы там, где это предусмотрено архитектурой»

## Разделы спецификации

§88 (C11); прежнее «Убери часы работы» (G04) остаётся в силе: график работы можно хранить, но на сайте он не выводится.

## Критерии приёмки

- [ ] `/admin/settings/store` с вкладками «Основные настройки», «Доставка и оплата», «Способы оплаты», «Склады и остатки», «Налоги и цены», «Email и уведомления», «SEO и метаданные» (вкладки ведут на страницы своих тикетов C12/C11; не реализованные к моменту сдачи показывают честное «Раздел в разработке» — итоговая проверка C13 требует, чтобы их не осталось), кнопки «Сохранить настройки» и «Сбросить изменения» в шапке
- [ ] **Основные настройки**: название магазина, слоган (по умолчанию слоган из брифа, редактируется), описание, логотип и favicon (загрузка PNG/JPG/SVG(PNG)/ICO с проверкой содержимого, размера ≤2 МБ/512 КБ; логотип показывается в шапке/подвале витрины, favicon в метаданных; предпросмотр), телефон, email, адрес, график работы (поле есть, но на витрине НЕ выводится), социальные сети (список «тип + URL», добавить/удалить, только http(s); выводятся в подвале только заданные), страна, регион, валюта (RUB по умолчанию; список ISO-кодов; деньги в системе остаются в копейках, смена валюты меняет только отображение/символ — оговорка на экране), часовой пояс (IANA; используется в отображении дат админки и витрины)
- [ ] **Переключатели** с серверным принудительным действием: «Включить магазин» (выключен → витрина отвечает 503 страницей «Магазин временно закрыт» с телефоном/адресом из настроек, админка и `/api/health` доступны), «Режим технического обслуживания» (503 с сообщением, сотрудники с активной сессией видят сайт с плашкой), «Показывать цены» (выключен → цены и кнопка «В корзину» скрыты, оформление заказа недоступно на сервере, API корзины отвечает отказом), «Разрешить регистрацию» (выключен → регистрация отклоняется на сервере, форма скрыта), «Требовать подтверждение email» (регистрация создаёт неподтверждённый аккаунт, письмо с одноразовой ссылкой через очередь; без подтверждения вход запрещён, если включено; при незаданной почте переключатель включить нельзя — предупреждение), «Защита форм от спама» (включает honeypot + лимиты; при выключении обязательные меры безопасности — лимиты входа, Origin — НЕ отключаются, только дополнительные; подпись об этом); все значения читаются кэшируемо (`getStoreFlags()` с коротким кэшем и инвалидацией при сохранении), тесты на каждый переключатель через публичные обработчики
- [ ] Хранение и применение: расширение `shop_settings` типизированными ключами (с валидацией zod по ключам) либо отдельной таблицей; значения по умолчанию совпадают с текущим поведением (миграция не меняет работающий сайт); название/слоган/описание/контакты/соцсети/логотип используются в шапке, подвале, метаданных, JSON-LD Organization, письмах; метки-заглушки остаются там, где значение не задано (никаких выдуманных)
- [ ] **SEO и метаданные** (`/admin/settings/seo`, право `seo.write`): название сайта, Meta Description по умолчанию, Open Graph (изображение по умолчанию, тип), canonical host/правила (https, www), robots (индексировать сайт глобально вкл/выкл, дополнительные Disallow-пути), sitemap (вкл/выкл разделов: товары, категории, страницы, новости, услуги; частота/приоритет по умолчанию), шаблоны title/description для товаров и категорий с переменными `{name} {brand} {category} {price} {site}` (проверка шаблона, предпросмотр на реальном товаре), правила индексации (noindex для фильтров/сортировок/пустых категорий — из текущей реализации T11); влияние проверено тестами: `robots.txt`, `sitemap.xml`, `<title>/description/og:*/canonical` карточки и категории меняются после сохранения; индивидуальные SEO-поля товара/категории имеют приоритет над шаблонами
- [ ] Права: `settings.write`, `seo.write` (admin; manager — просмотр без секретов); Origin, zod, аудит (`settings.update` с до/после, без секретов), конфликт изменений (версия/`updated_at` — при расхождении понятная ошибка, а не молчаливая перезапись); `UnsavedChangesGuard`; адаптив (формы в одну колонку)
- [ ] `npm run check` и `npm run build` (NEXT_DIST_DIR=.next-c11) зелёные
