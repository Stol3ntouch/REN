# C05 — Таблица товаров: фильтры, массовые действия, дублирование, удаление, экспорт

**Требования:** G18
**Зависит от:** C04
**Зона:** `src/app/admin/(panel)/catalog/page.tsx` · `src/app/admin/(panel)/catalog/ProductTable.tsx` · `src/app/admin/(panel)/catalog/products/list/**` · `src/app/admin/api/products/**` · `src/app/admin/(panel)/_lib/product-list-ops.ts` · `src/server/db/repositories/{catalog-admin,products-admin}.ts` (только списки/массовые) · `src/domain/catalog/products-list.ts` · `tests/admin/product-list*.test.ts*`
**Волна:** 16
**Ревью:** нет
**Модель:** обычная

## Что должно заработать

Рабочая таблица товаров `/admin/catalog` в стиле образца (фото, наименование, артикул, категория, цена, наличие, статус-переключатель, дата, действия) с серверным поиском, сортировкой, фильтрами, пагинацией и массовыми действиями на большом каталоге.

## Из брифа, дословно

> «Реализуй: Поиск. Сортировку. Пагинацию. Настройку количества строк. Фильтрацию по категориям. Фильтрацию по брендам. Фильтрацию по наличию. Фильтрацию по статусу публикации. Фильтрацию по цене. Выбор нескольких товаров. Массовое включение и отключение публикации. Массовое перемещение в категорию. Массовое изменение доступных атрибутов. Дублирование товара. Удаление с подтверждением. Экспорт отфильтрованных товаров»
> «Пагинация и фильтры должны работать на уровне API и базы данных для больших каталогов»

## Разделы спецификации

§88 (C05).

## Критерии приёмки

- [ ] Серверный список: `q` (название, SKU, штрихкод), сортировка по названию/цене/дате/остатку/категории, страница и размер (10/20/50/100, по умолчанию 20), фильтры: категория (с подкатегориями), бренд, наличие (`availability`), публикация/скрытие, диапазон цены, новинка/рекомендуемый/акция; параметры в URL, ответ `{items,total,page,pageSize}`; запрос использует индексы (тест: на 1214 товарах список открывается ≤ N SQL-запросов и без полного чтения таблицы фото; N зафиксировать)
- [ ] Таблица (`DataTable` kit): фото-миниатюра, название и краткое описание, артикул, категория, цена (+старая), остаток (число), наличие-бейдж, переключатель публикации (мгновенное сохранение с откатом при ошибке), дата, действия (редактировать, дублировать, удалить, меню «ещё»); состояния загрузки/пусто/ошибка; закупочной цены нет без права
- [ ] Массовые действия на выбранных строках и «все по фильтру» (до 5000, с подтверждением числа): публикация/снятие, скрытие/показ, перемещение в категорию (основная), смена бренда, флаги новинка/рекомендуемый/акция, добавление в дополнительную категорию; каждая — в одной транзакции, идемпотентна, с отчётом «изменено/пропущено/ошибок», в аудите одна запись с числом и фильтром; лимит и право `products.write`
- [ ] Дублирование товара: копия получает новый slug (суффикс), пустой SKU/штрихкод или уникальный суффикс, скрыта (`published=0`), без остатка, с копией характеристик, категорий и ссылок на изображения; Удаление: ConfirmDialog, правила C04 (при заказах — предложение скрыть); массовое удаление — только товары без заказов, остальные пропускаются с причиной
- [ ] Экспорт отфильтрованных (`/admin/api/products/export?…` CSV UTF-8 с BOM, разделитель `;`, экранирование формул `= + - @`): те же фильтры, колонки (id, sku, название, категория, бренд, цена, старая цена, остаток, наличие, публикация, slug; закупочная — только при `products.cost`), лимит строк и проверка права `export.run`/`products.read`; файл формируется потоком/порциями
- [ ] Права: просмотр `products.read`, изменения `products.write`, удаление `products.delete`, экспорт — по ключам из `interfaces.md` (после C02 доступны); manager без `products.write` видит таблицу без кнопок изменения; прямые запросы → 403 (тесты); Origin, zod
- [ ] `npm run check` и `npm run build` (NEXT_DIST_DIR=.next-c05) зелёные
