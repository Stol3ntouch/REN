# C07 — Единый модуль импорта и экспорта: CSV и YML

**Требования:** G28
**Зависит от:** C04, C05
**Зона:** `src/importing/**` · `src/app/admin/(panel)/import/**` · `src/app/admin/api/import/**` · `src/app/admin/(panel)/_lib/import-ops.ts` · `src/server/db/repositories/{import-runs,import-mappings}.ts` · `migrations/1300-1349` · `scripts/import-yml.ts` · `tests/importing/**` · `tests/admin/import*.test.ts*` · `tests/fixtures/**`
**Волна:** 17
**Ревью:** нет
**Модель:** сильная

## Что должно заработать

Раздел «Импорт / Экспорт»: загрузка CSV или YML, проверка структуры, предварительный просмотр, сопоставление колонок, режимы «только добавить» и «обновить существующие», отчёт по строкам, история операций и экспорт каталога с учётом фильтров.

## Из брифа, дословно

> «Создай единый модуль импорта и экспорта. Поддержи CSV и форматы, используемые существующей системой»
> «Не применяй частично повреждённый импорт так, чтобы оставались непредсказуемые изменения. Используй транзакции для атомарных операций там, где это допустимо»
> «Не выполняй загруженный файл как код. Ограничивай размер, формат и количество обрабатываемых записей»

## Разделы спецификации

§88 (C07); существующий импорт YML (T02, `applyImport`, `locked_fields`).

## Критерии приёмки

- [ ] Мастер из шагов: «Файл» (загрузка, определение формата CSV/YML по содержимому, а не расширению; лимит 20 МБ и 50 000 строк; CSV: UTF-8/UTF-8 BOM/windows-1251, разделители `,` `;` табуляция определяются; кодировка/разделитель можно поправить вручную), «Сопоставление» (колонки файла → поля системы: sku, название, slug, цена, старая цена, остаток, категория (путь `Родитель > Дочерняя` или код), бренд, штрихкод, описание, публикация, изображения (URL), характеристики `attr:<код>`; сохранение пресета сопоставления с именем для повторного использования; автоподбор по заголовкам), «Проверка» (обязательные поля, типы, дубли по SKU/внешнему ID внутри файла и в базе, неизвестные категории/бренды — режим «создавать» или «ошибка»), «Предпросмотр» (первые 50 строк с вердиктом создать/обновить/пропустить/ошибка и итоги), «Применение»
- [ ] Режимы: «только новые» (существующие по SKU/внешнему ID пропускаются), «обновить существующие» (по выбранному ключу `sku|external_id|barcode`; пустые ячейки не затирают значения, если не выбрано «очищать пустые»); поля, правленные вручную (`locked_fields`), не затираются, если не отмечено «перезаписывать ручные правки» (право `import.run` + подтверждение)
- [ ] Атомарность: применение — пакетами по ≤500 строк, каждый пакет в транзакции; режим «всё или ничего» (одна транзакция до 5000 строк) и «пакетный» (ошибочные строки пропускаются, в отчёт); при критической ошибке пакет откатывается и остаётся отчёт; выполнение не блокирует сервер более нескольких секунд на пакет (порции + запись прогресса `import_runs.progress`, страница показывает ход)
- [ ] Отчёт: созданных/обновлённых/пропущенных/ошибок, таблица ошибок построчно (номер строки, поле, причина) с выгрузкой CSV; история запусков (`import_runs`: тип, формат, файл, режим, пользователь, время, итог) с повторным открытием отчёта; повтор того же файла — 0 дублей (идемпотентно); изображения по URL — только через `safeFetchImage` (allowlist, SSRF) и только по галочке
- [ ] Существующий импорт YML сохранён и использует тот же мастер (CLI `npm run import:yml` продолжает работать); полный реальный файл `inputs/catalog.yml` (1214 товаров) проходит тестом через мастер; CSV-тесты на фикстурах: корректный, с ошибками, повреждённый, в windows-1251, с формулами `=cmd` (хранятся как текст и не исполняются), с BOM, слишком большой
- [ ] Экспорт: CSV по тем же полям (с сопоставлением в обратную сторону) и по фильтрам товаров (из C05), экспорт заказов/клиентов выносится в их разделы; закупочная цена — только с `products.cost`; файл формируется порциями; право `export.run`; экспорт товаров не называется «резервной копией»
- [ ] Права `import.run`/`export.run` (admin), manager — только история; Origin, zod, аудит (`import.run`, `import.apply`, `export.run` с числом строк); уведомление `notify()` об ошибке импорта (после C02); `npm run check` и `npm run build` (NEXT_DIST_DIR=.next-c07) зелёные
