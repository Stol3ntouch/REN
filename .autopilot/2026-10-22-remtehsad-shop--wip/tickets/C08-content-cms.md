## Что должно заработать

Единый CMS-контур контента: страницы с черновиками, предпросмотром и отложенной публикацией; баннеры с привязкой к позициям и категориям; новости с категориями и автором; акции с правилами и участвующими товарами; купоны; отзывы с ответом администратора; услуги. Всё хранится в базе, редактируется в админке и реально выводится на сайте.

В этой волне права проверяются старым ключом `content.write` (и `promos.write`, `reviews.moderate`).

## Из брифа, дословно

> «Реализуй CMS-редактор страниц… Статус публикации. Дата публикации. SEO. Превью. Черновик. Редактирование опубликованной страницы. Не допускай XSS при отображении HTML»
> «Баннеры… Не выдумывай рекламные утверждения. Сохраняй тексты, внесённые администратором»
> «Не допускай применения несовместимых скидок и некорректных итоговых цен»
> «Не создавай фиктивные отзывы и оценки»

## Критерии приёмки

- [ ] **Страницы** (`/admin/content/pages`): список (системные и созданные админом), создание новой страницы (slug уникален, не пересекается с системными маршрутами, формат `/pages/<slug>`), правка: заголовок, slug, содержимое, изображения (вставка загруженных через безопасное хранилище), статус `draft|published|scheduled`, дата публикации (`published_at`; запланированные появляются сами по времени), SEO (title, description, canonical, индексация), предпросмотр черновика по одноразовой подписанной ссылке (виден только вошедшему сотруднику), редактирование опубликованной с сохранением версии (история ≥5 последних версий, откат); содержимое — структурированный безопасный формат (расширенный Markdown/блоки: заголовки, абзацы, списки, ссылки, изображения, цитаты; без сырого HTML), вывод экранируется/санитизируется; тест на XSS (`<script>`, `onerror`, `javascript:`); удалять системные страницы нельзя (скрыть можно, кроме политики ПДн)
- [ ] **Баннеры** (`/admin/content/banners`): таблица `banners(id, title, image_path, mobile_image_path, alt, heading, subheading, button_text, url, position ('home_hero'|'category'|'top_strip'|…), starts_at, ends_at, sort, status, created_at)` + связь с категориями `banner_categories(banner_id, category_id, sort, enabled)`; слайды главной (`slides`, максимум 3 в позиции hero) мигрируют в баннеры без потерь; URL только http(s)/относительный; активность по датам; изображения JPG/PNG/WebP через `src/media`; выбор баннера для категории (используется C06); на главной баннеры позиции `home_hero` вместо слайдера, ограничение 3 сохраняется; тексты админа выводятся как есть (экранируются)
- [ ] **Новости**: заголовок, slug, превью (excerpt), содержимое, изображение, дата публикации и планирование, автор (сотрудник или текст), статус, категории новостей (`news_categories`, список/фильтр на `/news`), SEO; пагинация на витрине
- [ ] **Акции и скидки**: `promotions` расширены: условия (текст), период (`starts_at/ends_at`), тип скидки (`percent|fixed|none` — только информирующая или применимая), участвующие товары/категории (`promotion_products`), ограничения (мин. сумма, лимит), приоритет, статус; правило совместимости: на товар действует не более одной применимой акции (максимальный приоритет), скидка не делает цену ≤0 и не превышает цену; итоговая цена считается на сервере в копейках; несовместимые акции не сохраняются (понятная ошибка, тест); страницы акций на витрине отображают только активные по датам; **купоны** (`/admin/promos`) — существующие, плюс: «один купон на заказ», несовместимость с акционной ценой по выбору, отчёт использований
- [ ] **Отзывы** (`/admin/reviews`): список с фильтрами статус/товар/оценка/период и пагинацией, модерация (опубликовать/отклонить/в ожидание), ответ администратора (`admin_reply`, `replied_at`, `replied_by`) показывается под отзывом на витрине, дата, автор, товар; рейтинг — только по опубликованным; никаких фиктивных; отзывы о компании — как раньше
- [ ] **Услуги** (`/admin/content/services`): название, описание, изображение, цена или условие стоимости (текст «от …»/«по договорённости» — не выдумывать, пусто допустимо), категория услуги (`service_categories`), статус, порядок, SEO; форма заявки на ремонт остаётся на странице услуги; список на `/services`
- [ ] Общее: список каждой сущности с серверной пагинацией/поиском/сортировкой на `DataTable`, действия создать/правка/дублировать/скрыть/удалить (ConfirmDialog), `SaveBar`+`UnsavedChangesGuard`, права (admin; manager — просмотр, прямой запрос → 403), Origin, zod, аудит, изображения — только через `src/media`; прежний контент не теряется (миграции переносят, тесты на данных 0500–1000)
- [ ] `npm run check` и `npm run build` (NEXT_DIST_DIR=.next-c08) зелёные
