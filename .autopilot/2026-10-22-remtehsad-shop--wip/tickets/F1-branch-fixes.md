## Критерии приёмки

- [ ] **Лимит входа без доверенного прокси.** При `TRUST_PROXY=false` (или невозможности определить IP) общий бакет `'unknown'` НЕ блокирует чужие входы: тест — 6 неудачных входов в admin/покупателя с `ip='unknown'` не запрещают вход с верным паролем; ключ блокировки при неопределённом IP строится только из логина (не из общего IP) с мягким лимитом, а общие лимиты форм (`form:*:unknown`, `reset:ip:unknown`, заявки/отзывы) при `ip='unknown'` не применяются как общий бакет на весь сайт; в production при `TRUST_PROXY` не заданном явно — предупреждение в логе при старте (без секретов), задокументировано в `.env.example` комментарием
- [ ] **Secure-cookie по окружению.** `sessionCookieOptions` (`src/domain/customers/session.ts`) берёт `secure` из `isProductionEnv()`; тест: при `APP_ENV=production` без `NODE_ENV` у cookie покупателя и сотрудника `secure:true`
- [ ] **Маскирование аудита.** `maskPii`/`audit.record` заменяют значения под ключами по `/pass(word)?|token|hash|secret|authorization|cookie/i` на `[скрыто]` на любой глубине; тест: `{after:{passwordHash:'x',nested:{token:'y'}}}` не содержит `x` и `y`
- [ ] **Тест на защиту админ-страниц.** Тест в `tests/rbac` читает файловую систему: каждый `src/app/admin/(panel)/**/page.tsx` содержит вызов `requireStaffPage`, каждый `route.ts` и `actions.ts` — `requirePermission`/`withStaffPermission`/`requireStaff`; явный список исключений только для `/admin/login` и `(auth)/**`
- [ ] **Описание товара очищается на выводе.** `getProductBySlug` пропускает `descriptionHtml` через `sanitizeDescription`; тест: `description='<p>a</p><img src=x onerror=alert(1)><script>x</script>'` в БД → HTML страницы без `img`/`script`/`onerror`
- [ ] **Дубль parseVariants.** Одна экспортируемая `parseVariants` (в репозитории images), остальные импортируют; `grep "function parseVariants" src` даёт 1 результат
- [ ] **Дерево категорий читается один раз на запрос.** На странице категории `categoriesRepo.listAll` вызывается не более одного раза (React `cache()` или передача параметром); результат страницы не меняется; тест на число вызовов
- [ ] **Кэш картинок категорий сбрасывается.** После `applyImport` и после правки фото товара вызывается `clearCategoryImageCache()`; тест: после импорта с новым фото плитка категории показывает его сразу
- [ ] **Промокод возвращается при отмене.** При переходе заказа в `cancelled` (и `payment_failed → cancelled`, отмена из 1С, возврат до исполнения) в той же транзакции `used_count` уменьшается не ниже 0 ровно один раз на заказ (признак «возвращён», миграция в `migrations/0800-0849`); тест на двойную отмену и на повторный `place` после отмены
- [ ] **Возврат не зависает.** `orders.refund` при платеже, уже `refunded`, не вызывает провайдера и лишь доводит заказ до `refunded`; платёж в `refund_pending` старше таймаута подбирается и сверяется; тест «сбой `transition` после возврата → повторный возврат завершает заказ»
- [ ] **Заказ не теряется при сбое старта оплаты.** В `checkout/actions.ts` ошибка `startOnlinePayment` перехватывается отдельно: покупатель всё равно получает редирект на `/order/...?placed=1` (с пояснением «оплатить можно позже»); тест с падающим стартером
- [ ] **Webhook: размер тела и лимит.** При `content-length` > 64 КБ или фактическом превышении при чтении — 413 без буферизации всего тела; неудачные 401/400 учитываются в `rateLimit` по IP (при известном IP); причина пишется в журнал без тела запроса; тест
- [ ] **Письма с пустым payload не уходят.** Письмо с пустым/неполным payload не отправляется (терминальный `failed` с причиной), `requeue` отказывает для писем с очищенным payload; тест (сброс пароля после очистки не уходит пустым)
- [ ] `npm run check` и `npm run build` (с `NEXT_DIST_DIR=.next-f1`) зелёные; ни одно существующее утверждение тестов не ослаблено
