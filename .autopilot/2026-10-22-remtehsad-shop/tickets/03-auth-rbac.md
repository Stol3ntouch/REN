## Что должно заработать

Покупатель регистрируется, входит, выходит и восстанавливает пароль по одноразовой ссылке. Сотрудники (admin, manager) входят на отдельной странице `/admin/login` со своей сессией. Админ-оболочка: боковая навигация по разделам схемы, пункты скрыты по правам, но каждая операция проверяет права на сервере. Первый администратор создаётся командой `npm run admin:create`. Журнал аудита работает. Гостевая корзина при входе переходит к пользователю (`getOwnerRef` учитывает сессию).

## Критерии приёмки

- [ ] Пароль хранится только как scrypt-хеш с солью; токен сессии — только хеш в БД; cookie `HttpOnly`, `SameSite=Lax`, `Secure` в production
- [ ] Пароль <10 символов, невалидный email, повторная регистрация дают понятные ошибки; ответ сброса пароля не раскрывает существование email
- [ ] 5 неудачных входов за 15 минут для пары email+IP → временная блокировка (тест с управляемым временем)
- [ ] Ссылка сброса одноразовая и живёт 1 час; повторное использование и просроченная отклоняются (тест)
- [ ] `/admin/*` без сессии сотрудника → редирект на `/admin/login`; сессия покупателя не открывает админку и наоборот
- [ ] Тест-матрица: для каждого `Permission` и каждой роли `requirePermission` отвечает по таблице спецификации; прямой вызов защищённого обработчика менеджером возвращает 403
- [ ] `audit.record` пишет событие, записи нельзя изменить через репозиторий; email и телефон в аудите и логах маскируются
- [ ] `npm run admin:create` создаёт admin; пароль берётся из ввода или env и не печатается
