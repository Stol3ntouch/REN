# Спецификация: интернет-магазин «РемТехСад»

## Задача
Владелец небольшого магазина садовой техники хочет сайт, где покупатель находит товар, кладёт его в корзину и оформляет заказ без звонка, а любой посетитель может оставить заявку на ремонт. Сотрудники (администратор, менеджер) принимают заказы и заявки в закрытой админке. Каталог придёт из реальной выгрузки (YML, `inputs/catalog.yml`: 1218 товаров, 185 категорий), позже — из 1С. 1С, эквайринга и доставки пока нет.

## Решение
Готовое локально запускаемое приложение: публичный сайт на русском (mobile-first), корзина и заказ для гостя и пользователя, личный кабинет, избранное и сравнение, отзывы с модерацией, заявки (ремонт, звонок, вопрос, обратная связь), админка с двумя ролями, импорт YML с предпросмотром и отчётом, SEO и почтовые уведомления. 1С, оплата, доставка и почта подключены через **интерфейсы с локальными заглушками**; реальные поставщики добавляются без правки доменной логики. Всё, что ждёт факта от владельца (логотип, адрес, телефон, юридические тексты, часы, реквизиты), — видимая метка-заглушка.

## Решения по реализации (с причиной)

| Решение | Почему |
|---|---|
| **Next.js (App Router) + TypeScript**, модульный монолит | Лучшее SEO (SSR), одно приложение, нет PHP-стека/Open Server; ответ на «какой лучше — тот и бери» |
| **SQLite** (встроенный `node:sqlite`, либо `better-sqlite3`, если `node:sqlite` недоступен на Node 26 — выбирает T01 и фиксирует в ADR), доступ только через репозитории | На машине нет ни PostgreSQL, ни Docker; 1218 товаров и один склад — SQLite достаточно; бэкап = один файл. **Это отклонение от предложенного в брифинге PostgreSQL**; переезд на PostgreSQL возможен, т.к. SQL скрыт за репозиториями (ADR-001) |
| SQL-миграции версионированные, файлами `migrations/NNNN_*.sql`, раннер со своей таблицей версий | Нет ORM-привязки к диалекту; миграции тестируются |
| Валидация — `zod` на всех границах (формы, API, импорт, webhooks) | Единая серверная валидация |
| Пароли — `crypto.scrypt` с солью; сессии — случайный токен, в БД хранится только хеш, cookie `HttpOnly; SameSite=Lax; Secure` в production | Без нативных модулей, без самодельной криптографии |
| Деньги — целые копейки (`integer`), валюта RUB | Нет ошибок округления |
| Тесты — Vitest (unit/integration на временной БД); E2E-сценарии — Playwright, если браузер доступен, иначе скрипт-проверка через HTTP (T-тикет фиксирует, что именно запущено) | Реальные проверки, честный отчёт |
| Поиск — SQLite FTS5 (`unicode61`) по названию и модели + нормализованное сравнение артикула | Без внешнего сервиса |
| Изображения: импорт скачивает с allowlist-хостов (по умолчанию `champion.ru`), проверяет тип/размер, перекодирует и режет на размеры (`sharp`, если встаёт на Node 26; иначе — сохраняет проверенный оригинал и пишет это в отчёт) | SSRF-защита, скорость, независимость от чужого хоста |
| Карта — Leaflet + OpenStreetMap, только когда в настройках заданы координаты | Нет ключей; пока нет адреса — «адрес не указан» |
| Почта — `nodemailer` (SMTP по env) за портом `MailPort`; без SMTP — запись в таблицу `email_outbox`, видна в админке | Не теряем уведомления, нет выдуманной отправки |

## Данные каталога (из YML, факты проверены по файлу)
- `offer@id` → `externalId` (источник `yml`), `name`, `model` → артикул (**ASSUMPTION**: `vendorCode` в файле нет, `model` есть у всех 1218), `categoryId`, `price` → копейки, `picture` (до 25), `description` (есть у 315), `param@name` → характеристики, `available` true/false → «в наличии»/«нет в наличии» (**количеств нет**, остаток числом не показываем).
- Старой цены (`oldprice`) в файле нет → «скидочная цена» хранится в модели, заполняется вручную/из 1С, пока пусто — блок «Акционные» скрыт.
- Slug товара — последний сегмент `<url>` (champion.ru), при конфликте — суффикс; slug категории — транслитерация названия.
- `package_photos`, `url` не импортируются как контент.
- Фильтры: характеристика становится фильтром категории, если встречается у ≥3 товаров категории и имеет ≤30 различных значений; плюс диапазон цены и «только в наличии». Никаких характеристик «от себя».
- Права на фото и описания из чужого фида (champion.ru) — **открытый вопрос владельцу**, в отчёте.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Импорт CSV/XLSX | формат не согласован (в брифе «после согласования формата»); YML (XML) работает |
| «EML» | значение не подтверждено — по ТЗ не реализуем |
| Реальные 1С, эквайринг, доставка, SMTP | нет выбора поставщиков и доступов; порты и заглушки готовы |
| Склад: поступления/списания/инвентаризация, резервы | 1С — источник; остатков числом в данных нет |
| Маржа / валовая прибыль | нет закупочной цены |
| Комплекты/бандлы, автоматические скидки | правила скидок не согласованы (есть только промокод) |
| Режим «удалить отсутствующее в файле» | рискованно, нужен отдельный режим и подтверждение |
| Учёт стадий ремонта и запчастей | исключено брифом |
| Отдельные роли (content_manager и др.) из пакета 2 | пользователь выбрал пакет 1 |
| Docker, CI-запуск, деплой в production | Docker не установлен; публикация — только по отдельному согласию |
| Бренды как сущность, массовое редактирование товаров | в YML нет поля производителя/бренда (весь фид «champion»); массовые правки — следующий заход |
| Сопоставление полей при импорте | формат YML фиксирован, маппинг в коде; нужен только при CSV/XLSX |
| Документы товаров (PDF, инструкции) | в фиде нет документов |
| Реальный выбор и проверка совместимости конфигурации 1С | нужен выбор владельца и партнёра 1С; в `docs/1c.md` — список вопросов из `1/docs/13` |
